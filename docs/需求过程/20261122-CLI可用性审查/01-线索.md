## 三、建议增加的功能

| 对象 | 建议 | 理由 |
|---|---|---|
| btf | `bt check --full`（或 `--with-l5`） | 把 L5 22 例纳入一键门禁；默认仍 10 项，显式开启才耗时 |
| btf | `bt data quality --st-symbols`（或 `--st-from namechange`） | 修复 C-P1-1，让 ST 分支可用 |
| btf | `bt test --layer` 加 `choices=("l1","l2","l3","l4","l5","all")` | 笔误立即报用法错 2 |
| btf | `bt optimize --resume <state.json>` | 长扫描可续跑 |
| btf | `bt runs --json` / `bt show --latest` | 自动化消费最近 run |
| 主工程 | `db health`（聚合 doctor + freshness + audit + fingerprint 摘要，`--strict`） | 一键巡检，替代 4 条命令 |
| 主工程 | `db audit --json`（stdout） | 统一 JSON 口径 |
| 主工程 | `gap-update --table` 兼容别名（映射到 `--only`） | 兼容旧文档/肌肉记忆 |
| 主工程 | `main.py --help` 按「数据维护 / 研究分析 / 推送导出 / 诊断」分组 | 可发现性 |

## 六、优先级与待裁定

| 优先级 | 条目 |
|---|---|
| 第一优先（正确性） | C-P1-1 ST 名单、C-P1-2 freshness 默认严格、C-P1-3 audit JSON |

1. `bt check --full` 是否纳入 L5（单次约 64 分钟）？
2. `db freshness` 默认是否改 strict（会影响现有日更脚本退出码）？
3. 干跑开关统一为 `--apply` 还是保留 `--execute` 为主？
4. 是否新增 `db health` 聚合命令？
5. `gap-update --table` 是否加兼容别名（还是坚持文档用 `--only`）？
6. `bt data quality` 的 ST 名单来源：`namechange` 自动推导，还是新增配置项？

## 八、需求方裁定（2026-11-22）

> 6 问均同意，按以下口径落地；本节为后续路线图的输入。

| # | 问题 | 裁定 |
|---|---|---|
| 1 | `bt check --full` 是否纳入 L5 | **纳入**。`--full` 时追加 L5 22 例；默认仍 10 项。help 与 19 号手册标注「`--full` 单次约 64 分钟」 |
| 2 | `db freshness` 默认是否改 strict | **默认 strict**：存在红/黄表时 exit 1；新增 `--no-strict` 显式放宽。同步改日更 bat 与看门狗脚本，避免既有流水线因退出码变化误停 |
| 3 | 干跑开关统一 | **主推 `--apply`**；`--execute` 保留为同义别名（向后兼容），help 标注「同义」。涉及 `db backup`、`db ckpt`、`db stale-fix`、`db meta-close`、`schedule` |
| 4 | 是否新增 `db health` | **新增**。聚合 `doctor` + `db freshness` + `db audit` + `db fingerprint` 摘要；`--strict` 可 exit 1；`--json` 输出 stdout |
| 5 | `gap-update --table` 兼容别名 | **新增**，映射到 `--only`；help 标注「同 `--only`，兼容旧文档」 |
| 6 | ST 名单来源 | **`namechange` 自动推导**（PIT，取当日有效 ST 状态）；`--st-symbols` 作为显式覆盖。无名单时不得静默跳过，输出 WARN 并记录「ST 分支未生效」 |

**落地顺序（供路线图参考）**：

1. 正确性：ST 名单（#6）→ freshness 默认 strict（#2）→ audit JSON（C-P1-3）
2. 可用性：check --full（#1）→ db health（#4）→ layer choices / --latest / optimize --resume
3. 一致性：干跑开关（#3）→ gap-update --table（#5）→ help 分组 / 隐藏别名展示 / action 缺省统一
