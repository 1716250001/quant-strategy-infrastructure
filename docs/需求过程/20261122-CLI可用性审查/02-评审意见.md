## 二、必须修正的 4 处

### 2.1 主工程可见命令数：26 → **30**（基线错误）

- [parser.py](file:///D:/量化策略/代码/cli/parser.py#L158-L518) 实际注册 **30** 个可见顶层命令；`main.py --help` 也列出 30 个。
- 01 §一表格写「26 可见」，但同格列出的命令名恰为 **30** 个（gap-update…etf-flow），属内部自相矛盾。
- 复核计数：`visible=30`、`hidden=10`、`db 子命令=13`、`btf=14`；后三者与 01 一致。

### 2.2 C-P1-3 不成立：`db audit --json` 已是 stdout

- [db_cmds.py](file:///D:/量化策略/代码/cli/db_cmds.py#L257-L275) 的 audit 用 `_add_json`，即 `action="store_true"`；[cmd_db_audit](file:///D:/量化策略/代码/cli/db_cmds.py#L61-L84) 把 `as_json` 传入 `run_audit`。
- [audit.py](file:///D:/量化策略/代码/tools/db/audit.py#L1546-L1562) 在 `as_json` 时用 `print_json` 写 stdout，不写文件。
- 01 引用的 `cli/db_cmds.py:355 --json PATH` 实际是 **`db scale-check`** 的参数；`db audit --help` 的 `--json` 无 PATH。
- 若仍要保留「JSON 口径不统一」，应改写为：**`db scale-check --json PATH` 是文件路径、且仅 `--stats` 使用；与 `db audit/freshness/schema/report` 的 stdout JSON 不一致**。

### 2.3 C-P3-4 不成立：`bt dataset` 有缺省动作

- [main.py](file:///D:/量化策略/代码/btf/btf/cli/main.py#L822-L830) `_args_dataset` 的 `action` 为 `nargs="?"`、`default="build-golden"`。
- `bt data` 缺省为 `scan-consolidation`（[main.py](file:///D:/量化策略/代码/btf/btf/cli/main.py#L782-L790)）。
- 因此不是「一个有缺省、一个无动作」，而是「两个都有缺省，但缺省语义不同（扫描 vs 构建）」。建议把线索改写为：**是否把两者的缺省都改为「无动作时打印动作列表并 exit 2」**；这是设计取舍，不是既存 bug。

### 2.4 C-P2-1 的例子 `l4 ` 不是笔误

- `l4` 是合法测试层：`pytest -m l4` 实测收集 **78** 例；`l1|l2|l3|l4|l5|all` 均在用。
- [main.py](file:///D:/量化策略/代码/btf/btf/cli/main.py#L508-L511) 确实没有 `choices`，问题成立；但笔误例子应改为 `l6`、`l4x` 或 `l4 `（作为带空格字符串）才能触发「no tests ran / exit 5」。

## 四、漏报 / 需补充的线索

1. **顶层 `freshness` 没有 `--strict`**：`db freshness` 有 `--strict`，顶层 `freshness` 走 [quicklook.py](file:///D:/量化策略/代码/tools/quicklook.py#L121-L137) 的兼容代理，签名里没有 strict。若按需求方裁定把「默认 strict」落地，必须同时覆盖两个入口，否则 `main.py freshness` 仍恒 0。
2. **`db` 顶层帮助摘要只列 6/13 子命令**：[parser.py](file:///D:/量化策略/代码/cli/parser.py#L293) 的 `db` help 写「audit/schema/report/clean/migrate/ckpt」，遗漏 freshness/scale-check/schema-align/fingerprint/meta-close/backup/stale-fix。`db --help` 子命令列表是全的，但顶层摘要会误导。
3. **`bt data quality` 当前无 ST WARN**：源码 docstring 要求 CLI 侧 `[warn]`，但 `_cmd_data` 的 quality 分支未打印；需求方裁定 #6 要求「不得静默跳过」，落地时须补 WARN，不能只加参数。
4. **JSON 口径的真正不一致点是 `db scale-check`**：`--json PATH` + 仅 `--stats` 使用（[db_cmds.py](file:///D:/量化策略/代码/cli/db_cmds.py#L349-L356)），与 audit/freshness/schema/report 的 stdout JSON 不同；建议把 C-P1-3 改指向它，或降为 P3。
5. **`gap-update --table` 兼容别名**：当前只有 `--only`；加别名时需明确与 `--group` 的优先级，否则 P3-2 的歧义会被放大。
6. **`db health` 成本**：聚合 `db audit` 全量（D10 实测 `index_daily` 915MB/69.4s）与 `db fingerprint`（全库哈希）可能远超「一键巡检」预期；建议 health 默认走轻量摘要/最近结果，`--full` 才跑全量。
