## 目录分工

| 子目录 | 回答什么问题 | 入口 |
|---|---|---|
| `代码架构\` | 系统**怎么设计、为什么这么设计**、改了谁验收 | `代码架构\README.md` |
| `运维手册\` | **怎么用、怎么排障**（进程、依赖、环境） | `运维手册\README.md` |

## 三、需求过程（活跃期入库，结项即归档）

一个需求一个目录：`需求过程\<YYYYMMDD>-<简述>\`，文件序号即流转顺序：

```
01-线索.md      ← 需求方（启动会话）
02-评审意见.md   ← 审查会话
03-路线图.md     ← 总控会话
04-编码记录.md   ← 编码会话
04A-编码复审意见.md ← 审查会话（分档编码的中间复审，可选）
05-验收.md       ← 审查会话复审
06-编码复审意见.md ← 审查会话（返工复审，可多次：06/07…）
```

- 状态台账：`需求过程\INDEX.md`
- **派单开工前失败基线**：执行会话开工前须记录全量 `pytest tests`（或 L4 子集）的
  `collected / passed / skipped / failed` 与失败清单；验收以「无新增失败」对比，
  不得仅凭因果链判定（REQ-20261121-01 F8 教训）。
- **结项后整体移入** `备份\归档文件\需求过程\<同名>\`，台账保留一行索引
- 本目录入库，但**不受** `test_doc_claim_guards.py` 的数字守卫约束（过程文档的数字是当时记录，不必随代码漂移）
