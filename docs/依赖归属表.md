## 一、五份文件的角色（先认清，再动手）

| 文件 | 角色 | 包数 | 谁读它 | 改了会影响 |
|---|---|---|---|---|
| `pyproject.toml` | **主工程开发视图**——只写直接依赖，宽松版本，说明"代码引用了什么" | 7 runtime + 2 dev | `pip install -e .`、setuptools 打包 | wheel 元数据、`pip install` 解析 |

**一句话**：`pyproject` 声明"要什么"，`requirements` 锁定"要哪个版本"，`lock.txt` 是"这台机器上现在有什么"。

## 二、决策树：加一个依赖，改哪几份？

```
新依赖 X 要加
│
├─ 只被 btf 用？
│   ├─ 是 → ① btf/pyproject.toml 的 dependencies（或 optional）
│   │       ② btf/requirements.txt 锁版本
│   │       ③ 先跑 `python btf/tools/deps_budget.py` 确认槽位（当前 8/8 已满！）
│   │       ⚠ 槽位满时须走 ADR 例外或先回收一个槽位，不得硬塞
│   │       ④ 追加 btf/CHANGELOG.md
│   │       ✗ 不动根三份（btf 与主工程已解耦，2026-10-24 裁定）
│   │
│   └─ 否 ↓
│
├─ 只被主工程用？
│   ├─ 是 → ① pyproject.toml 的 dependencies（**运行时**）
│   │       ② requirements.txt 补冻结版本
│   │       ③ requirements.lock.txt **不手改**（下次 `pip list --format=freeze` 重生成）
│   │       ④ 若只在某条 CLI 路径用（如导出 Excel），仍属 dependencies —— 见 §3 反例
│   │
│   └─ 否 ↓
│
└─ 两边都用 → 按"主工程"路径走（根三份），btf 侧只在 btf/requirements.txt 里锁版本，
              并且在 btf/pyproject.toml 注释说明"底座由主工程提供"（现状即如此）
```

## 三、已知缺陷（2026-11-04 实测，未修，登记在此）

### 缺陷 1：`openpyxl` 被误归 dev，实际是运行时依赖

| 项 | 事实 |
|---|---|
| 声明位置 | `pyproject.toml` `[project.optional-dependencies] dev = ["pytest", "openpyxl"]` |
| 实际引用 | `tools/export_lof.py:12` `import openpyxl` —— 活代码，被 `main.py lof-export` 调用 |
| 后果 | `pip install .`（不带 `[dev]`）后 `python main.py lof-export` 直接 `ImportError` |
| 现状为何没爆 | 本机 `_venv` 装了全部 69 包（`requirements.lock.txt` 口径），所以看不到 |

**修法**（属 W6 `DEP-02`/`DEP-03` 同批）：把 `openpyxl` 从 `dev` 移到 `dependencies`，`dev` 只留 `pytest`。移动后 `pyproject` 的 dependencies 变 8 个，与 `requirements.txt` 头部"8 个直接依赖"的表述一致。

### 缺陷 2：`requirements.txt` 头部计数与实际不一致的隐患

`requirements.txt` 头部写"8 直接依赖（pandas numpy akshare pyarrow requests scipy tushare openpyxl）"，而 `pyproject.toml` 的 `dependencies` 只有 7 个（缺 openpyxl）。两份文件对"直接依赖"的定义不同：一份按"代码 import 了"，一份按"运行时必需"。

**修法**：同缺陷 1，一次性对齐。

## 四、版本冲突裁决规则

三条，按序适用：

1. **`requirements.txt`（冻结实测）优先于 `pyproject.toml`（宽松声明）** —— 前者是在这台机器上跑通过的。
2. **`requirements.lock.txt` 优先于 `requirements.txt`** —— 前者含 btf 依赖与传递闭包，覆盖更全；但它只作参考，不作为安装指令（头部已注明"勿据此行安装"）。
3. **同一包在两处版本不同且都"能跑"时，不做选择，先记录** —— 在 `docs/进程管理.md` 的"环境异动"节登记差异与发生日期，等下次重建环境时统一。

## 五、发版后必做（承接 `CFG-04`）

**这是 2026-11-04 已经踩过的坑**：多次发版只改 `_version.py` / `config.py`，没重装，导致 `pip list` 显示 `btf 1.3.4` / `pyramid-strategy 5.0.0`，而源码与 git tag 都是 `7.0.0`——差 5~6 个 major。

**发版检查单加一步（硬性）**：

```bash
cd D:/量化策略/代码
_venv/Scripts/python.exe -m pip install -e . --no-deps -q
cd btf && ../_venv/Scripts/python.exe -m pip install -e . --no-deps -q
cd .. && _venv/Scripts/python.exe -c "
import importlib.metadata as M
from btf._version import __version__ as bv
import config
assert M.version('btf')==bv==config.__version__==M.version('pyramid-strategy'), 'MISMATCH'
print('VERSION OK', bv)"
# 期望：VERSION OK 7.0.0（或当次版本号）
```

**为什么要 `--no-deps`**：避免重装时顺手升级已锁定的依赖，把"只改版本号"变成"改环境"。

## 六、校验命令（随时可跑）

```bash
cd D:/量化策略/代码

# 1) 声明与锁文件是否覆盖一致（缺项会列出来）
_venv/Scripts/python.exe - <<'PY'
import tomllib, pathlib, re
d = tomllib.loads(pathlib.Path("pyproject.toml").read_text(encoding="utf-8"))
declared = {p.split(">")[0].split("=")[0].strip().lower() for p in d["project"]["dependencies"]}
frozen = set()
for line in pathlib.Path("requirements.txt").read_text(encoding="utf-8").splitlines():
    line = line.split("#")[0].strip()
    if line and not line.startswith("-"):
        frozen.add(re.split(r"[<>=!]", line)[0].lower())
print("声明未冻结:", sorted(declared - frozen) or "无")
print("冻结未声明:", sorted(frozen - declared) or "无（含传递依赖属正常）")
PY

# 2) 每个 import 的第三方包是否都声明了（粗筛，靠人工判读）
grep -rhoE "^(import|from) [a-z_]+" --include="*.py" . \
  --exclude-dir=_venv --exclude-dir=_python --exclude-dir=.git \
  --exclude-dir=_archive --exclude-dir=_scratch \
  | awk '{print $2}' | sort -u | head -40

# 3) btf 依赖预算
_venv/Scripts/python.exe btf/tools/deps_budget.py
```

## 七、与 `.env` 的边界

依赖表**只管包**，不管凭据。凭据纪律见根 `README.md` §9 第 1 条：只在 `.env`，永不进仓。

`_scratch/` 与 `_archive/` 存在历史明文凭据（详见 `_scratch/README.md` 的警示节），**它们不属依赖问题，但同样禁止外发**。
