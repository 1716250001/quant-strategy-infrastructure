# 12 架构决策记录（ADR）

> **本文档汇总 btf 当前生效的架构决策**——对应实现版本 **btf 1.2.4（2026-10-10 发版）**（沿革：1.0.0 定版 2026-09-29 → 1.1.0 CLI 收编 2026-09-30 → 1.2.0 配股/缩股入链路落版 2026-10-07 → 1.2.1 工具完备版 → 1.2.2 完备收口版 → **1.2.3 公司行动扩维＋收口五轮（V1.2.3 定版，2026-10-09）** → **1.2.4＝定版后 L4 阶段六单并入（R57′~R62′，2026-10-10 发版）**：R57′（`optimize --objective` 基准同源）／`walk-forward` 预热修复（R58′）／`lookback_bars` 声明（R59′）／**文档守卫 4 组＋纪律九**（R60′）／**折算感知 FIFO**（R61′）／**消费侧价格视图 `run.price_view`（默认 qfq）**（R62′）；口径以本文档正文为准）。

## ADR-1 采用「分层可插拔 + 事件驱动内核」

- **决策**：领域核心零第三方依赖；**结论只出自事件驱动层**；数据/成本/滑点/风控/指标/存储全部插件化。
- **现状**：`btf.domain`（白名单标准库）→ 引擎四模块 → 分析/实验/数据 → `btf.app` → `btf.cli`/`btf.api`；**10 条 import-linter 契约**机器守卫。
- **依据**：A 股约束（T+1/涨跌停/停牌/ST）在事后修正层无法穷尽验证；事件层逐事件可查、可单测。
- **边界**：向量化仅用于筛选与校验（参数扫描、数据不变量校验），**不作结论**。

## ADR-2 数据存储：直读现有 Parquet 主库（标准层与 DuckDB 未采纳）

- **决策**：btf **只读**直读 `market_data`（年分区 Parquet）；`tables_meta` 登记 **20 表**三布局（数据字典 21 项——第 21 项 `fund_share` 不注册，仅披露、禁判折算）；读取层统一布局与量纲。
  （**2026-10-05 修订并已交付（RC-04）**：18 → 19，新增 `fund_adj`（起点 19991022）——ETF 份额折算 / 不定期折算的复权因子**唯一来源**，
  路由见 `tables_meta.factor_table_of`（股票 → `adj_factor`；ETF/LOF → `fund_adj`），见 [05 §9.4](05-数据架构与数据集体系.md)。ADR-2 结论不变，仅登记数变化。
   **2026-10-07 再扩（DOC-8/ADR-20）**：19 → **21 项**（`tables_meta` 登记 **20 表**）——新增 `fund_div`（ETF/LOF 分红）与 `fund_share`（仅披露，禁判折算）；**R32′ 已交付（2026-10-08）**：`fund_div` 登记为第 20 表、`fund_share` **不注册**（仅披露、禁判折算——ADR-20 第 6 条）；ADR-2 结论仍不变。）
- **现状**：`btf.data.parquet_reader`（谓词下推、`memory_map` 仅主库）+ `core.YearTableStore`（唯一 IO 入口、有界缓存、线程安全）。
- **未采纳（保留评估）**：中间"Parquet 标准层"与 DuckDB 查询层——当前规模下 PyArrow 足够，引入即引入第二套口径与额外构建负担。
- **性能证据**：子集宇宙谓词下推使十年全市场回测 **32.9s**；LIQ 十年预计算 **4.95–4.97s**。

## ADR-3 单进程起步，进程池并行，不引入分布式与消息中间件

- **决策**：事件循环单进程（确定性优先）；参数扫描用 `ProcessPoolExecutor`（含 initializer 预热）；预计算用 `ThreadPoolExecutor`（pyarrow 释放 GIL）。
- **现状**：`btf/optimize/grid.py`（workers 缺省 8）；`data/liq.precompute_liq_series`（逐年并行 + 共享 store 加锁、IO 在锁外）。
- **边界**：无 MQ、无分布式、无调度服务（NG4）；**进程池是唯一并行手段**。

## ADR-4 配置体系：分层合并 + JSON Schema 校验 + 禁硬编码路径

- **决策**：默认层 → `BTF_*` 环境 → 用户 YAML → CLI `--set`（`a__b=v`）；Schema `backtest.v1` **拒绝未知键**；路径可经环境变量覆盖。
- **现状**：`btf/config/{loader,validation,paths}.py`；`btf.app` 为覆盖解析唯一实现（`bt config-check [--resolve-strategy] [--dump]` 可预检）；`mask_config` 脱敏。
- **理由**：未知键静默忽略 = 用户以为生效实则未生效（真实事故类型）；死键必须在校验期暴露。

## ADR-5 事件模型：强类型事件 + JSONL 溯源日志

- **决策**：7 类事件（`market_open/close`、`order_submitted/rejected`、`fill`、`corporate_action`、`session_end`）以 frozen dataclass 定义；日志为 JSONL，可采样但**必须披露**。
- **现状**：`btf/domain/events.py` + `btf/engine/events_log.py`（预算前置 + 尾部 ring + 哨兵行 `kind="_sampled"`）。
- **边界**：事件日志是回放/对账依据，**不是**交易指令通道。

## ADR-6 复权与记账：名义价记账 + 公司行动按两时点入账

- **决策**：引擎以**不复权价**记账；除权/派息通过 `CorporateAction` 事件在 `ex_date`（份额/成本调整）与 `pay_date`（现金到账）分别处理；复权序列仅供研究与校验（**不进记账**）。
- **现状**：`btf/data/adjust.py`（`AdjustService`，消费侧）+ `btf/engine/loop.py` 步骤 ① + CC-4 因子一致性守卫。
- **理由**：复权基准漂移会污染成本/持仓与 NAV；名义价记账 + 事件调整是唯一可对账口径。

## ADR-7 入口策略：单一 Facade（`BTFRuntime`）+ 应用服务层 + 双入口

- **决策**：装配根唯一（`BTFRuntime`）；CLI 与 API **共用 `btf.app`**（同源实现，天然字节等价）；入口层不得含编排（契约 10）。
- **现状**：`btf/runtime.py` + `btf/app/services.py` + `btf/cli/main.py`（**13 命令族**，1.1.0 后新增 `validate`，**1.2.3 新增 `data`**——R34′/V1.2.3）+ `btf/api.py`。
- **边界**：不提供 REST/gRPC/Web（非目标）。

## ADR-8 实验管理：自建轻量 RunStore（不引入 MLflow/W&B）

- **决策**：产物 = 目录 + JSON/JSONL + HTML；四版本锁定写 `manifest.json`；对账用 `metrics_digest` + `bt verify`。
- **现状**：`btf/experiment/{store,manifest}.py`（`local_jsonl`、原子写 + fsync、状态机 `RUNNING/COMPLETED/FAILED`、manifest 主版本校验）。
- **理由**：无需服务端；纯文本产物**可 diff / 可 audit**，与"可复现优先"一致。

## ADR-9 规则参数单一真源：RulesProvider 对接赤潮规则源

- **决策**：规则数值**禁止**在 YAML 手抄；经 `rules: {source: mirror_json|static, path: …}` 声明加载；仅显式 `override: true` 的研究变量可覆盖。
- **现状**：`rules_provider` 注册点 + `rules_version`/`rules_overrides` 入 manifest + **四方机检**（源 ↔ 镜像 ↔ 消费绑定 ↔ btf 缓存，含状态机语义锚点）。
- **理由**：规则升级后"行为是否漂移"必须有可比对基准，手抄即失去基准。

## ADR-10 研究层（向量化）不作为结论来源（API 未交付）

- **决策**：不交付向量化研究 API；研究需求由 **`btf.data` 读取层 + Notebook** 满足；参数扫描由 `grid_search`（走标准引擎链路）承担。
- **现状**：`btf.optimize.grid`（每组合 `load_config → build → run`，与单跑逐位一致）；**无** 向量化回测入口。
- **理由**：两套口径的治理成本高于收益；研究结论不进入验收证据链。

## ADR-11 依赖管理：最小依赖集 + 依赖预算门禁

- **决策**：运行依赖保持最小（pyarrow/numpy/pyyaml/jsonschema + 可选 plotly）；`pandas` 仅研究与测试；不引入编译型扩展；依赖预算常跑门禁。
- **现状**：`pyproject.toml` + `tools/deps_budget.py`（`bt check` 第 4 项）；`matplotlib` 不引入（图表用 Plotly 或内置降级渲染）。
- **理由**：单人维护下"少依赖 = 少升级风险"。

## ADR-12 摩擦默认非零：滑点与流动性约束缺省即生效（2026-10-05 立，RC-01/RC-02）

- **决策**：
  1. 缺省**不是**零摩擦——滑点缺省 `pct 0.001`（单边 10bp，业界保守下限），成交量参与率上限 **VPP 缺省 0.05**（单笔 ≤ 当日成交量 5%，超出缩量，不足一手 `volume_cap` 拒单）；
  2. **显式放松仍允许**（`slippage.model: none` / `volume_participation: null` / `cost_model: zero`），但必须 `warn` + 进报告「假设与披露」（与既有 `cost_model: zero` 告警对称）；
  3. 摩擦假设**不是硬编码**——报告一律读 `config_effective`（ADR-4 的"死键/假生效"同源纪律）；
  4. 默认口径变更 = **结论口径变更**：交付前后须 A/B 双跑，且"改了必须有差异"。
- **依据**：实测 98 份历史 manifest **100% 零滑点、100% 无流动性约束**——默认零摩擦使"默认跑出来的数"系统性乐观，且用户往往不知道自己跑在零摩擦世界；
  保守默认 + 显式放松，把"我要零摩擦"变成一个**需要声明、会被披露**的动作。
- **边界**：本 ADR 只管**默认与披露**，不管摩擦的**精度**——规模相关滑点已由 **RC-12 交付**（`sqrt_impact`，**默认关闭**；η/σ/cap 为**研究口径**，须自行标定来源）；
  缺省值本身是可调的研究参数，但"非零"这条不可回退。
- **状态**：**✅ 已生效（2026-10-05 交付）**——RC-01（滑点缺省 `pct 0.001`）/ RC-02（VPP 缺省 `0.05`）落地，
  删除了"深合并残留"两个陷阱（非 `pct` 模型的 `pct` 键剥离；空 dict = 显式清空），见 [04 §8.5.1](04-领域模型与核心接口.md) 与 [18 §九·C](18-分步编码计划.md) 交付留痕。

## ADR-13 推断层边界：btf 只做"可见化"，不做策略有效性判定（2026-10-05 立）

- **决策**：
  1. btf 交付 **L4 可见化**（试验数 `N`、PSR/DSR、邻域退化率、成本敏感性参数位），**不交付"策略有效 / 无效"的判定**；
  2. 判定在**框架外**（置换检验 / Walk-Forward / 成本敏感性复跑），由使用方负责；
  3. 未经框架外推断的结论，一律表述为「**零摩擦假设下的记账结果**」——btf 是**记账机不是裁判**（[01 §1.1](01-总览与定位.md)）。
- **依据**：L4 推断层近乎空白这一事实**此前未被写入使用纪律**，导致"记账准"被误读为"结论已被证明"；
  把 N 与 DSR 做成产物字段，是最低成本地把"试得越多越不可信"变成**使用者无法忽视**的数字。
- **边界**：Walk-Forward / 蒙特卡洛**已立项**（老大 2026-10-05 裁决；**Q2 追认后派单文档已补编号 RC-15 / RC-16**，编号体系重新对齐），但仍属"可见化"，**不替用户下结论**；
  版本门禁（RC-14）属可复现域，不属判定域。
- **状态**：**生效**（纪律立即生效；**实现部分已交付**——RC-06/07（2026-10-05）+ RC-15/16（`bt validate walk-forward\|mc`，2026-10-05；独立复核见 19 号 §65））。

## ADR-14 文档同步纪律：未交付的代码修改不得写成现状（2026-10-05 立，老大裁决）

- **决策**：
  1. **代码未交付 ⇒ 说明文档（使用指引 / CLI 手册等）不改**——避免"文档先行、实现滞后"的漂移；
  2. 架构文档（01–17）中**可以**登记派单内容，但必须写成「**目标态 + ⏳ 状态标记**」，并注明当前代码的实际行为；
  3. B 域同步的**完成动作在代码交付批次内**一并执行（A 域改行为 → 同批改 B 域章节），不在交付前单独改。
- **依据**：本项目已多次因"声明 vs 事实"付出代价（19 号累计十余处）；文档先行等于制造新的漂移源。
- **边界（2026-10-05 按 Q3 裁决澄清；订正 DOC-3-2）**：按**是否依赖代码交付**二分——
  ① **纪律类**（约束**人的行为**：结论表述降级纪律、「btf 是记账机不是裁判」使用纪律、基准跑前定死、危机区间不得事后挑选）⇒ **立即生效、立即写入说明文档**，**不受本 ADR 限制**；
  ② **配置 / 参数类**（默认值表、CLI 参数与选项、schema 新键、能力矩阵中的能力条目）⇒ **交付后生效**，随 RC 交付批次同步。
  **本 ADR 只约束 ②**；**不得以本 ADR 为由拒改或延后 ①**（此前正是此误解导致 20/21 号纪律类被判"不补改"）。
- **状态**：**生效**（本次 RC 批次起适用；01–17 中 RC 相关描述已逐处补 ⏳ 标记；边界二分已于 2026-10-05 订正）。

## ADR-15 公司行动数据路径：离线探针清单，不建主库管道（2026-10-07 立，CL-2 第二段/Q-4(a)）

- **决策**：配股/缩股数据**不写入主库**（`adj_factor` 消费逻辑 INV-12 不动）；由本地探针
  （`adj_factor` 跳变 ∩ 分红排除 ∩ akshare 快照关联）产出**离线清单** `btf_datasets/corp_actions/corp_actions.json`
  （带来源快照 sha256），feed adapter 按区间注入。
- **依据**：主库只读纪律 + "数据不入库"原则；离线清单可 diff/可审计/可重生成，且不阻塞发版（N16/N17 修复只动清单与判据）。
- **状态**：**✅ 生效**（1.2.0 交付；**R12′ 起覆盖 175 条配股**（实际发行比例 `r_eff` 判定——1.2.2）；挂起 **1** 条（`300176.SZ` 真噪声）附股本级披露 `r_effective`/认购率/`forward_err_eff`——N19，仅披露不建模）。

## ADR-16 配股校验：正推判据为主 + 放大因子守卫（2026-10-07 立，N16/G1+G2）

- **决策**：校验一律**正推** `chg_pred = X(1+r)/(X+r·Pr)`（放大因子 ≈1、数值稳定），容差 0.5%；
  反向式仅在 `amp = chg(1+r)/|1+r−chg| ≤ 5` 时作辅助；`amp > 5` **禁反推**。
- **依据**：反向式在配股价折价小时分母趋零（实测挂起组中位 10.4x/最大 39.5x），曾误杀 79 条真配股
  （known-16 中 6 条被判死）；正推重算 86/86 全过、挂起组 79/90 救回。
- **状态**：**✅ 生效**（1.2.0；`_validate_right_math` 纯函数＋单测）。

## ADR-17 缩股代理：默认只披露、不建模（2026-10-07 裁决，N17/G3/§80.6）

- **决策**：缩股佐证判据收紧（容差 5%→1%＋比例 ≤0.95＋同标的单次）后 **0 条存活**；且事件未被交易所公告确证
  ⇒ **默认只披露、不建模**（`BTFTOOL_CORP_ACTIONS_CONSOLIDATIONS` 显式开启才建模）。
- **依据**：建模输入不可信（71% 同标的重复触发、0.99x 非真实缩股方案）；默认档不得让冻结口径（v77 三档）无谓漂移（实测开启漂移 −0.010~−0.048pp）。
- **状态**：**✅ 生效（强制）**；判据 D（股本级 `r_eff` 建模）出 1.2.1（**Q-6 已裁并落地**：`pex` 三级取值＋`pex_source` 披露——R19′/1.2.1）。

## ADR-18 长区间 run 终值不可作判据：判定下沉「首次分歧日＋当日分解」（2026-10-07 立，N20/R14′）

- **决策**：5,040 日路径依赖 run 对 ≤0.3% 扰动终值放大约 33 倍且符号可反转 ⇒ **单点终值不得作为结论依据**；
  修复/回归判定用「首次分歧日 ＋ 当日股数/现金/NAV Δ（`M×(P−Pr)`，P＝除权日有效价）＋ `n_fills` 差」
  （对账产物 `divergence` 字段）。
- **状态**：**✅ 生效**（20 号纪律五；R10′/R13′-b 已交付）。

## ADR-19 发版口径：v1.2.0 不宣称"前三层完备/D7 完全闭合"（2026-10-07 立，G10/§81.4）

- **状态**：**生效·已裁定（2026-10-09/10；19 号 §117.1）**——老大裁定可对外表述「**前三层（L1–L3 工具层）全通**」（弃用含混的「前三层**完备**」；**「四层全通／L4 已完成」仍禁**），并附 **L4 已启动**（五条判据全部有产出；② 为混合结论，引用须带全折分布＋warm-up 口径）；「Q-4(a) 全额行权／缩股仅披露／不构成策略有效性背书」三条保留不变。

## ADR-20 ETF/LOF 公司行动入账：分红（`fund_div`）＋ 份额折算（双证据）（2026-10-07 立，CL-2-H/§92；DOC-7）

> 溯源：19 号 §92（ETF 公司行动专项审查）/ §93.2 DOC-7 / §94.2（Q-9=(a′) 裁决落地）。
> **已交付（2026-10-08；CL-2-H 第二阶段）**：R32′→R35′→R34′→R36′（＋R26′ 指标口径）按序落地，
> 19 号 **§97.8 验收通过**（逐单实跑取证；N29~N37/N39 闭合）；本 ADR 由「草案/⏳ 目标态」转为**实现现状**。
> 版本随 **V1.2.3 定版（老大 2026-10-09 裁定）**——收口五轮（R37′~R54′/R56′，共十九单、
> N40~N59 逐项闭合）经 **§103 独立验收通过**，**G-EXIT-1~5 全部满足**；1.3.0 不再立版。

- **① 扩维声明**：ADR-6「名义价记账 ＋ 两时点公司行动」的**主体从「股票」扩维到
  「股票 ＋ 场内基金（ETF/LOF）」**；**ADR-6 原文不改写**（只增不减）。扩维只新增基金侧
  数据源与判定规则，**记账语义与股票侧完全同构**。
- **② 分红入账（两时点，照搬 ADR-6 股票语义）**：`ex_date` 份额不变（除息价由行情承担）；
  `pay_date` 现金到账 `qty_at_pay × div_cash`。数据源 `fund_div`（主库已具备；`tables_meta`
  **已登记为第 20 表**——R32′，2026-10-08）。主口径 **`pay_date`**（实测池内 **39/39 笔** `pay_date` 非空、`earpay_date`
  反为空）；**回退链**：`pay_date` 缺失 → `earpay_date` → `ex_date`，**任何回退必须披露**；
  `pay_date` 若为非交易日 ⇒ **顺延至下一交易日**入账并披露。
- **③ 金额口径（硬约束）**：`div_cash` **即每份金额，直接乘份额**；**禁止除以 `base_unit`**
  （`base_unit` 是参与分红的份额基数，量级 2.4 万~72 万；误除将把分红缩小约 5 个数量级）。
  实证锚点（复现脚本 `_scratch/audit_etf_corp_action.py`）：510880 **11/11 笔** `div_cash`
  与「前收 − `pre_close`」**零误差**吻合。
- **④ 去重与状态过滤**：入池前按 `(ts_code, ex_date)` **去重**（实测 510310 于 2024-10-21
  存在 2 条同金额行，不去重将**双倍入账**）；**只消费 `div_proc == '实施'`**
  （全库存在 20 条「分红方案待定」——不去将把**未实施分红**记账）。
- **⑤ 份额折算入账（双证据）**：折算比 **R ＝ `pre_close(t) ÷ close(t−1)`**（交易所除权价，
  权威），与 `fund_adj` 因子跳变**独立互校、容差 0.5%**；不符 ⇒ **fail-closed ＋ 报告披露**，
  **不得静默取其一**。入账规则：**`shares ÷= R`、`avg_cost ×= R`**（成本总额守恒；与股票
  `consolidation_ratio` 同构，Q-6 口径分离同样适用）。**R 必须支持非整数**
  （实测 512200 ＝ **2.7937**、515580 ＝ **0.51003**；**逐事件反推，禁止查表/取整假设**）。
  **★ 互校方向（DOC-13，2026-10-07；N37——规格歧义，实现前必读）**：`fund_adj` 因子跳变
  **＝ R 的倒数**（分红使因子上升、合并份额使因子下降），互校式为
  **`|R × (f_t ÷ f_{t−1}) − 1| < 0.5%`**（实测 8 只 9 事件 `R×(f_t÷f_{t−1}) = 1.0000 ± 0.0002` 全部成立：
  510310＝2.00063×0.49980＝**1.00012**；512200＝2.79365×0.35800＝**1.00013**；515220＝0.50000×2.00000＝**1.00000**；
  515880＝0.33323×3.00100＝**1.00000**）。**禁止直接比较 R 与因子比值**——若按字面直接比较，
  偏差将达 **75%~800%** ⇒ **全部事件被判 fail-closed、功能等于失效**（19 号 §96.2-N37）。
- **⑥ 禁用条款**：**禁止用 `fund_share` 判定折算**（实测 510310 折算日份额
  6,234,724 → 6,240,394，仅 +0.09%；159995 折算日份额完全相同 ⇒ 误用将得出「无折算」的
  错误结论）；`fund_share` **只可作辅助披露**。
- **⑦ 成本模型品种维度**：ETF/LOF **免印花税**（判定复用 `domain/types.py` 已存在的
  `is_fund_code`）；过户费等其他科目**维持现状**。⚠ 本条款改变历史 run 的费用数值，
  属**数值型变更**——**已交付**（R24′ 并入 R36′，2026-10-08）：510880 run 印花税归零
  （原误收 11,448.88 元）、股票侧费用**逐位不变**（§97.4 回归）。
- **⑧ 披露与门禁（N33 改判后的工具侧责任——§92.12）**：宇宙含 ETF/LOF 且区间**跨越
  折算日/除息日** ⇒ 必须**告警 ＋ 报告披露**「本 run 策略信号基于**名义价**，存在跳变失真」；
  **不要求改指标口径**（指标保持名义价＝与真源/B1 一致）。
- **⑨ 已裁决口径（2026-10-07 22:08 老大裁 A；§94.1 消歧为 (a′)——不再留占位）**：
  - **Q-9（指标口径）＝ (a′)**：**保持名义价**（与真源 / B1「84 条序列零差异」一致）
    **＋ 记账补齐公司行动 ＋ 强制披露/门禁**；**不装配 `AdjustService` 进引擎**，
    不改 `feed`/`runtime` 取价链路。**已否决候选（留档）**：§92.9 原始 (a)（指标改 hfq
    ——需真源同步改造 ＋ B1 契约重定义；**若老大另行明示指向此项，本 ADR 回退重写**）；
    (c) 双轨 `--adjusted` 开关（未采纳，可另议）。
  - **Q-7（记账口径）＝ 现金到账为默认**（与 ADR-6 股票侧一致）；**再投仅作显式开关
    （可选、非默认）**，报告须标注所用口径。
- **⑩ 分红/折算判别与同日顺序（R43′/R45′，2026-10-08；N46/N49——§98.4）**：
  - **判别（语义优先于幅度）**：分红与折算在双证据上**数学同构**（除息日
    `f_t = f_{t−1} ÷ R` ⇒ `R × ρ = 1`，不可区分），故**折算候选日与 `fund_div`
    除息日交叉**——**同日存在除息记录 ⇒ 判为分红、不计折算**（`|jump|>12%` 幅度
    阈值不再是唯一防线；全库可比分红 >12% 共 218 笔、最高 70.47%＝184721.SZ
    2008-04-03，若按幅度误判将「份额凭空 ×3.39 ＋ 分红现金同时入账」双重错误）；
  - **同日同标的顺序＝先折算后分红**：分红现金按**折算后**份额计（`qty_at_ex`
    取当日折算完成后的持仓）。池内 0 实例（边界定义；实测 8 只 9 事件无交叉）。
  - **作用域（R53′/N57，2026-10-08）**：本第 ⑩ 条**只为 ETF/LOF 而立**——排序键
    （`action_order_key`）对非基金标的使用**中性第三键**（不改其相对次序，＝R49′ 前
    逐位一致）；**不得默认扩权至股票侧**，如需扩须先裁决。
  - **交叉防线 fail-safe（R51′/N55）**：`fund_div` 表缺失/不可读 ⇒ 交叉判别**不可用**
    （扫描报告 `cross_disabled=true` ⇒ 退出码 2，禁按成功结果引用）；「有行但过滤后为空」
    （`div_proc`/`div_cash<=0` 全滤）⇒ **三元计数披露**（原始/过滤跳过/入账）。
- **⑪ 碎份口径（R45′，2026-10-08；N48——§98.4）**：折算入账份额按 **`int()` 向下
  取整、丢弃不补偿**；**丢弃量逐事件披露**（`qty_fraction_dropped`，报告折算行可见），
  **不得静默消失**。实证：510310 折算日 777,700 × 0.499843798812871 ＝ 388,728.522… ⇒
  入账 388,728、丢弃 **0.522 份**（六位近似 0.499844 下为 0.68 份——同量级；口径以
  全精度 ratio 为准）。
- **⑫ 比率归一化与无效值口径（R54′，2026-10-08；N58/N59——§101.3/§101.4/§102.1）**：
  所有**外部读入**的比率字段（`consolidation_ratio` 等）一律经**统一 helper**
  `btf.domain.action.ratio_or_default(value, *, default=1.0, field, context)`：
  - `None` ⇒ `default`（无值＝无该行动，静默）；
  - **不可转换为 float**（`""`／`"abc"`／NaN／∞）⇒ `default` ＋ **WARN**（**禁崩**——
    N58：`is not None` 只兜 `None`，`float("")` 直接 `ValueError`）；
  - **`≤ 0` ⇒ 视为无效值 ⇒ 不建模（份额不变）** ⇒ `default` ＋ **WARN**——
    **禁止**流入缩股 R21′ 保底（`int(qty×0)=0` ⇒ 持仓被清零至 1 股）。
    **老大 2026-10-08 裁决 (a)**：宁可漏记一次缩股，不可摧毁持仓（不可逆资产破坏）。
  - 覆盖：`corp_action_probe`（确证＋代理两条装载路径）／`events_log._dec_action` 回读／
    `etf_corp_actions.action_order_key`／`portfolio` 消费端（五处收敛）。
  - **勘误 #17（§102.6）**：「`is not None` 优于 `or 1.0`」**只适用于「0 是合法业务值」
    的字段**；对**外部数据读入且 0/空为非法**的字段，`or` 与 `is not None` **皆非**正确
    形态——正确做法是上述统一 helper。
- **⑬ 折算贯穿分析层（R61′，2026-10-10；N63-a/N63-b——§113.2/§113.3/§114.2）**：
  份额折算**不只作用组合层**——分析层的 **FIFO 开平配对**（`trades` 产物与逐笔口径
  `win_rate_trades`）**必须感知折算**：折算时点对队列内该 symbol 的**每个 lot** 做
  **市值守恒变换**（**剩余数量 ×R**（碎份向下取整；`int(剩余×R) ≤ 0` ⇒ **R21′ 保底**
  ＝留 1 份、成本价不变）**且 成本价 ÷R**，多次折算**累积**）；**只对 `ex_date` 之前
  建立的 lot 生效**（同日/之后买入不受影响）；`_lot_pnl` 用**调整后成本价**、费用摊销
  分母＝**调整后**的 lot 原始量。**来源同源**：落盘路径＝`result.consolidations`；
  复核路径（`bt verify`）＝`events.jsonl` 的已应用 `corporate_action`（采样降级 ⇒ WARN）。
  **影响面边界**：NAV 口径主指标（`total_return`/`sharpe`/`max_drawdown` 等）**不受影响**；
  受影响者只有 `trades` 明细的未平仓数量与 `win_rate_trades`。**实证**：510580
  Σ未平仓 168,109 → **27,100**、`win_rate_trades` 1.0 → **0.667**、Trade#2 pnl
  **由错记盈利翻转为 −11,982（亏损）**（§九·AQ）。
- **⑭ Q-9 的「指标侧」分支细化（R62′/N64，2026-10-10；19 号 §117.4/§118）**：
  Q-9=(a′) 的**记账侧**结论不变（引擎记账＝名义价，ADR-6 不动）；其**指标/策略消费侧**
  分支由 R62′ 落实为 **`run.price_view`（默认 `adjusted`）**——喂给策略的 bar 走
  **qfq 后复权**（`qfq(t)=price(t)·f(t)/f(ref)`，`ref=run.period.start`；
  **PIT 合规**，**禁用 hfq**——hfq 依赖全序列因子 ⇒ 前视污染，比原缺口更严重）。
  边界：① 只改 ctx 的 `bar()`/`history()` 两个入口，撮合/成本/费用/NAV/快照**恒名义价**；
  ② 指数无复权语义、因子缺失回退 1.0＋披露（禁静默）；③ 覆盖段「指标口径」措辞随
  视图变化（不得再写「信号未复权」）。**实证**：510580 BOLL 带宽 **300.05% → 47.29%**
  （159922 名义 194.61% → 46.44%）；**记账侧 76 笔成交逐笔 `ref_price` == 名义开盘价**。
- **状态**：**生效·已定版**（Q-9=(a′)/Q-7＝现金到账默认已裁——19 号 §94.1/§94.3；编码
  R32′→R35′→R34′→R36′（＋R26′）已按 §96《解冻令》执行，**§97.8 验收通过**（2026-10-08）；
  收口五轮 **R37′~R54′/R56′（十九单）全清**（N40~N59 逐项闭合——§98/§99/§100/§101/§102），
  **§103 第六轮验收通过、G-EXIT-1~5 全部满足**（2026-10-09）；**随 V1.2.3 定版落版**）。
