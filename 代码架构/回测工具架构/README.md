## 一、本文档体系是什么

为"从 0 到 1 的专业量化交易回测工具"设计的**探索性、基础性、完整性架构文档**。它不是简单脚本或单策略演示的设计，而是覆盖数据、策略、撮合、组合、风控、绩效、优化、实验、工程化全链路的架构蓝图。

### 已确认的四项关键决策（2026-09-26）

| # | 决策项 | 结论 |
|---|---|---|
| 1 | **资产范围** | A 股优先——领域模型围绕 A 股（复权、涨跌停、T+1、公司行动、交易日历）深度设计，多资产作为远期扩展预留接口；**股票与 ETF 均进 MVP**（v0.2 修订：奇点战法=ETF 轮动是第一验收场景） |
| 2 | **数据底座** | 复用现有 Tushare 主库（`D:\全量数据\market_data`，111 表/6.33 GB）为 MVP 默认数据源（**只读**）；akshare 备库 v0.5 接入（v0.2 修订：MVP 不读 alt 库，表述对齐评审轻微 2） |
| 3 | **交付形式** | 多文件文档体系（本目录），按主题拆分，便于后续迭代维护 |
| 4 | **频率与性能** | 日线为主——向量化 + 事件驱动混合即可满足，性能压力小，探索期最务实 |

### v0.2 修订摘要（赤潮评审意见销项，详见 16 号文档 §32.6）

- **H1**：ETF 进 MVP；数据字典 12→17 表（+daily_basic/moneyflow/fina_indicator/index_weight/index_dailybasic）；"v7.7 规则引擎回归 + 奇点战法复跑"列为 v0.2 验收场景

- **S1-S5**：入账换算公式显式化（G1 第一断言）、卖先买后进 MVP、事件日志量级预算、btf vs md_core 口径对齐测试、研究层整体移 v0.5

- PoC 三项顺序与门槛**维持不动**（评审明确赞成）

### v0.3 修订摘要（二次评审销项，详见 16 号文档 §32.7）

- **H4（唯一阻塞项，已修复）**：v0.2 的 S1 公式（hfq 持仓成本）与 ADR-6 事件再除权构成**双重计算**（数值实证：af≠1 守恒式破坏、10送10 市值翻倍、派息凭空入账）。**采纳方案 A：引擎名义价记账 + 除权日事件调整持仓/现金**——ADR-6 改述、S1 公式集整体替换（含 CorporateAction.apply 显式公式）、守恒式与 adj_factor 解耦、PoC-3 断言按名义口径重写并加入 H4 数值反例回归锚点；hfq/qfq 序列仅用于研究层指标与展示
- **N1-N4**：字典口径 17 表同步（N1）；过户费三段修正（N2）；ADR 计数 10 项（N3）；BoardRule.t_plus ETF=1 修正（N4，境内 ETF T+1，与 09 B3 断言对齐）
- 二次评审结论：修复后**定稿 v0.3**，无需第三轮全量评审；冷却复审固定复核点 = 04 §8.2.6 与 09 §14.2（记账口径为最高危错误域）

### 三次评审与 v0.3 冻结（详见 16 号文档 §32.8）

- 三轮评审核销：**H4 + N1-N4 五项全部通过**（H4 经独立验算四案例确认彻底修复）→ v0.3 具备定稿条件
- **N5**：补 NAV/收益率定义公式（total_value/daily_return/cumulative_return/drawdown）；`Portfolio.market_value()` 重命名 `total_value()` 消歧；**收益归集加法禁区警示**（realized_pnl 已摊薄吸收分红，与分红现金相加即双重计算，总收益唯一真相 = total_value 口径）
- **N6**：G1 删"配股"（库内无数据源，MVP 不建模）
- **N7（方案 A）**：CorporateAction 增 `pay_date`；派息两时点拆分（ex_date 只摊成本、pay_date 入现金）；连续性断言拆分（送转单日 Δ=0 / 派息跨窗口合并 Δ=0）
- **v0.3 冻结**：评审仅需 diff 级复核三处（04 §8.2.6 / 05 §20.2 / CorporateAction）；PoC-1 可并行启动
- **四次复核（C1+B1）**：C1 修正 `qty_at_pay`→`qty_at_ex`（派息按登记在册数量到账，ex→pay 窗口内卖出不剥夺分红权；断言含该场景）；B1 披露窗口内无应收分红科目（2020+ 无影响，老数据轻微失真，v0.5+ 可选建模）——**v0.3 正式冻结**

### 文档写作纪律（贯穿全部文档）

- **不写生产实现代码**：仅允许接口签名（`typing.Protocol`）、伪代码、YAML/JSON Schema、Mermaid 图、表格。
- **标注体系全文统一**：
  - `[假设]` —— 基于合理推断的前提，尚未验证
  - `[待验证]` —— 需要 PoC 或实验确认的技术判断
  - `[开放问题]` —— 尚无结论、需要讨论或调研的问题
  - `[风险]` —— 已识别的可能影响目标达成的因素
- **区分探索期与生产期**：每个维度均给出 MVP 取舍，明确"先做 / 后做 / 明确不做"。
- 中文撰写，关键术语中英对照。
