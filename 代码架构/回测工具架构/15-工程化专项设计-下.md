## 第 27 章 偏差、过拟合与稳健性治理

### 27.1 已建防线

| 偏差类型 | 防线（当前实现） |
|---|---|
| **前视偏差** | 日循环 10 步全序 + 事件序固定；宇宙按当日 `universe(date)`；指数成分用**月末快照复算**；财务指标按 `ann_date`（PIT）；风控在决策时点用**当日盯市价** |
| **幸存者偏差** | 退市标的保留在库内（`stock_basic` 判退市而非删除）；含退市股的回测用例 |
| **成本低估** | 佣金/印花税/过户费按**日期分段**；缺省滑点 `none` 且在报告披露 |
| **约束乐观**（成交假设过松） | 无法建模的约束以**拒单**表达（停牌/涨跌停/整手）；`volume_cap`（量上限）显式拒单而非部分成交 |
| **数据错误** | 数据不变量校验 CC-1..CC-5（结构层）+ 内容指纹（变化可检出）+ 覆盖度守卫（越界 fail-closed） |
| **实现漂移** | 黄金集回归 + digest 双对账 + 规则四方机检（含状态机语义锚点） |

### 27.2 参数扫描与过拟合

- `grid_search` 诚实归档：**缺失/NaN 的 objective 排末尾但不剔除记录**（不掩盖失败组合）。
- **极短区间告警**：区间 < 20 交易日时告警且明确"勿用于 `optimize --objective` 排序"（极短区间指标数学有定义、业务无意义）。
- **不做**：Walk-Forward / 蒙特卡洛 / 多重检验校正（未实现，属能力演进项）；结论的稳健性判断当前依赖**多区间人工对照**（业务议题）。

### 27.3 结论表述纪律

- 报告必须同时给出：**区间**、**基准**（若配）、**成本假设**、**滑点**、**数据指纹**、**规则版本**——脱离这些的"收益率"不构成结论。
- 单区间结论不得表述为"策略有效"（策略有效性属研究体系议题，见 [11 §17.1 R-4](11-演进路线风险与PoC.md)）。

## 第 28 章 可观测性、运维与故障恢复

### 28.1 观测手段

| 手段 | 内容 |
|---|---|
| `bt run --verbose` | `step_timings`（装配·前置/质检/组件 ‖ 运行·指纹/引擎/落盘）+ 数据质检摘要 + 数据指纹摘要 |
| 日志 | 关键决策与降级走 `logging`（警告以上必现）；插件装载、覆盖度、质检、指纹均有日志 |
| 产物 | `manifest.json`（四版本 + 状态 + 说明）、`events.jsonl`（可采样但披露）、`data_quality_report.json` |
| 对账 | `bt verify --run <id>` → digest 双对账（recompute/stored） |
| 门禁 | `python tools/check.py`（9 项）+ `bt test --layer lN` |

### 28.2 故障分类与处置

| 故障 | 表现 | 处置 |
|---|---|---|
| 装配期失败 | 非零退出 + `[error] 装配失败：<异常类型>: <原因>` | 修配置/数据（硬门：覆盖率/基准/风控链/质检/档位/插件契约） |
| 运行期异常 | run 目录 `status=FAILED` + `error` | 保留现场，不自动重试；修因后重跑（新 `run_id`） |
| 数据越界 | `ConfigError` 指向具体表与起点 | 缩短区间或显式 `allow_degraded_limit=true`（并接受披露） |
| 性能回归 | 基准/门禁变红 | 查 `tests/perf/BASELINE.md` 的软/硬纪律与机器无关守卫（IO 计数/语义等值） |
| 产物可疑 | digest 不匹配 | `bt verify` 定位是 recompute 还是 stored 不一致；必要时重跑对照 |
| 半成品目录 | `status=RUNNING` 长时间不动 | 视为未完成；工具按状态读取（不误当结果） |

### 28.3 数据与产物的可恢复性

- **产物**：原子写 + fsync（文件 + 目录项）⇒ 掉电不产生"半个文件"。
- **数据**：只读主库；数据修复由采集侧重跑（btf 不介入）。
- **代码**：0.X 无版本级回退（**已知并接受**）；v1.0 定版日执行跨版本源码冷备（`cp -r`）。

## 第 29 章 互操作与 API 兼容

### 29.1 对外契约（S1，破坏性变更需 ADR）

| 契约 | 版本 | 消费方 |
|---|---|---|
| 运行结果数据契约 | `runresult.v1` | 报告（`viz`）、外部脚本、未来工具 |
| RunManifest | `runmanifest`（主版本校验） | 产物读取方（`bt report`/`bt verify`/脚本） |
| 回测配置 Schema | `backtest.v1` | 用户 YAML / `--set` |
| 数据质量报告 | `dataquality.v1` | 报告章节 + 脚本 |
| 领域/插件契约 | `CONTRACT_VERSION = "1.0"` | 全部插件实现 |

### 29.2 兼容策略

- **数据契约**：新增字段允许（消费方须容忍未知字段）；删改字段 = major。
- **插件契约**：注册期协商，不匹配**拒载**（不给"带病运行"的机会）。
- **CLI**：新增命令/选项向后兼容；选项语义变更须在 CHANGELOG 标注。
- **Python API**（`btf.api`）：仅三个函数（`run`/`report`/`dataset`），签名稳定；其余模块（`btf.data` 读取层等）为**内部接口**，不承诺兼容。

### 29.3 不做的互操作

- 不支持外部 CSV/其他数据源接入为"正式路径"（可经插件扩展，但不在承诺面内）。
- 不提供 REST/gRPC/HTTP 服务（NG6）。

## 第 30 章 开发者体验、治理与版本策略

### 30.1 开发者体验（当前）

| 场景 | 手段 |
|---|---|
| 快速上手 | `examples/`（样例策略 `rotation`/`buyhold` + 配置）+ `bt config-check --dump` |
| 写策略 | 继承 `StrategyBase`（`on_open`/`on_close` + `set_target`）；`--resolve-strategy` 预检可加载性 |
| 调试 | `--dry-run`（只装配）、`--verbose`（分步耗时）、`bt run --set` 覆盖、`MemoryFeed` 脱盘单测 |
| 找问题 | `bt verify`（digest 对账）、产物 JSONL 可读、门禁九项定位 |

### 30.2 治理（单人场景的"制度化"）

| 机制 | 内容 |
|---|---|
| **门禁常跑** | `tools/check.py` 9 项 + 五层测试；每批交付附实测摘要 |
| **契约机器化** | 10 条 import-linter + domain 白名单 + 插件边界（核心文件哈希基线 + **刷新留痕**） |
| **变更留痕** | CHANGELOG（含"措辞订正"回填）+ `tools/.plugin_baseline_history.jsonl` + 文档版本轴（[18](18-分步编码计划.md)） |
| **证据纪律** | 声称"真修/通过"须给实测摘要；防线必须**可被证伪**（负向对照）；披露字段**不得恒空** |
| **用语纪律** | 禁用"全绿"替代摘要；不得用"已修复"表述未能复现的问题（只能写"未能复现 + 已硬化"） |

### 30.3 版本策略

| 分级 | 版本规则 | 变更流程 |
|---|---|---|
| S1 契约级 | 语义化版本；破坏性 = major + 废弃期 | ADR + 全量回归 |
| S2 核心级 | minor 内兼容 | 回归 + CHANGELOG |
| S3 实现级 | 无承诺 | 自由迭代 |
| **工具版本** | `btf/_version.py` 单一真源（测试断言与包属性一致 + 形制校验） | 每批交付递增 + CHANGELOG 段落 |

**当前版本**：`1.1.0`（2026-09-30；1.0.0 定版于 2026-09-29）；「1.0」只对**工具**成立（可自证/自检/自退），体系恒演进（[16](16-架构评审与验收标准.md)）。

## 第 31 章 反模式与常见陷阱（清单，均来自真实缺陷）

### 31.1 结论层反模式

| # | 反模式 | 为什么危险 | btf 的对策 |
|---|---|---|---|
| 1 | **"全绿"代替实测摘要** | 掩盖假失败与覆盖盲区 | 证据纪律：命令 + 输出摘要 |
| 2 | **空洞披露**（字段恒为 `unknown`/占位） | 声称有、实为无 → 比不披露更误导 | 披露字段必须至少一次取真值；缺数据显式标注来源 |
| 3 | **伪防线**（断言正确但输入永不触发） | 造成"有守卫"的错觉 | 防线入列前做变异测试（故意破坏 → 必须变红） |
| 4 | **文本级断言冒充渲染级断言** | 转义/模板缺陷可结构性逃逸 | 交付物为渲染产物时，断言必须落到渲染后结构 |
| 5 | **计算链验证冒充系统级验收** | `persist=False` 的内部 API 调用绕过了落盘/报告链路 | 系统级结论必须经真入口（CLI → 落盘 → 报告 → 对账） |
| 6 | **等价测试互证**（两处共用同一错误实现） | "两家都对"其实是同一处错 | 序列依赖逻辑必须**序列推进**测试 + 分布锚点 |
| 7 | **手工构造历史序列**（如伪造 `prev_statuses`） | 真实推进下不可能出现的输入 → 验出错误结论 | 逐日推进、当日输出回灌次日输入 |

### 31.2 工程层反模式

| # | 反模式 | 后果 | btf 的对策 |
|---|---|---|---|
| 8 | **无界缓存** | 内存随时间/标的数增长 | 全部缓存有界（`BoundedDict`/`max_entries`） |
| 9 | **装配期做重活**（披露/审计类计算） | 每组合/每次装配重复付费（B4 曾超预算） | 披露计算推迟到落盘路径 + 先量后接 |
| 10 | **注释与事实不一致**（"无共享状态"实为共享） | 误导后续维护者 | 契约/机检优先；注释随证据更新（含"为何"） |
| 11 | **静默降级**（数据缺失→放行、越界→放行） | 结论被系统性污染且无人知晓 | fail-closed 默认 + 显式逃生开关 + **强制披露** |
| 12 | **死键/未消费配置** | 用户以为生效 | Schema `additionalProperties: false` + 代码扫描（残留清零） |
| 13 | **异步/并发无边界**（并发写同一缓存） | 非确定性结果 | 单进程事件循环 + 锁保护临界区（IO 在锁外）+ 装载双检 |
| 14 | **重启/重跑覆盖历史产物** | 不可追溯 | 每次运行新 `run_id`；报告再生成幂等但不改产物 |
| 15 | **硬编码路径/常量散落** | 迁移与复用成本 | 路径集中 `config/paths.py`（环境变量可覆盖）；阈值单源常量（如 `SHORT_PERIOD_TRADING_DAYS`） |

### 31.3 使用层提醒

- `--set` 的类型推断不会做布尔化（`true` 需在 YAML 中写 `true`）——避免 `"1"` 被误读为布尔。
- 报告 `sections` 收窄**不会**移除强制章节（假设与披露 / 复现说明）——这是刻意设计。
- 事件日志采样后**不可**用于逐事件回放（报告与 manifest 会标注采样）。
