# 02 参考系统对照与借鉴

> **本文档给出参考系统对照与「已采纳」的借鉴结论**——对应实现版本 **btf 1.1.0（2026-09-29 定版；2026-09-30 CLI 收编）**。
> 写作口径：只记录**当前生效的采纳结论**（采纳 → 落地位置；未采纳 → 原因），不保留取舍过程。
> 关联：分层架构见 [03](03-总体架构方案对比与推荐.md)；技术栈见 [07](07-技术选型建议与权衡.md)。

---

## 5.1 对照方法

- 对照维度：**事件模型 / 数据契约 / 撮合与约束表达 / 组合与目标表达 / 报告与可视化 / 实验管理 / 扩展机制**。
- 采纳标准：① 与"日线 + A 股微观约束 + 单人维护"匹配；② 能**机器化验证**（可写断言）；③ 不引入第二套口径或不必要组件。
- 记录形式：每个借鉴点给出 **落地位置**（可对照代码）与**状态**。

---

## 5.2 事件驱动型框架对照

| 系统 | 特征 | 借鉴结论（当前） |
|---|---|---|
| **LEAN**（QuantConnect） | 事件驱动 + 数据/算法分层 + 手续费模型化 | **采纳骨架**：事件循环 + 组件分层 + 成本模型参数化 → 落地 `btf.engine` / `btf.execution`；**未采纳**：双语言 DSL、云端环境、内置数据订阅 |
| **NautilusTrader** | 事件序列 + 强类型领域 + 撮合仿真精细 | **采纳**：事件类型强类型化（7 类 frozen dataclass）+ 确定性订单号 → `btf.domain.events`；**未采纳**：订单簿级撮合（无盘中数据）、actor 并发模型 |
| **Backtrader** | 回调风格 + 内置指标库 | **采纳**：策略回调面极简（`on_open`/`on_close`）→ `btf.strategy.base`；**未采纳**：内置指标库（指标归 `btf.analytics`，纯函数集中一处） |
| **QSTrader** | 组合/再平衡语义清晰 | **采纳**：目标仓位（TargetPortfolio）表达 + 再平衡器职责独立 → `btf.portfolio` + `rebalancer` 插件；**未采纳**：其数据接口形态 |

### 事件驱动类借鉴结论

**核心采纳 3 条**：① 策略只表达目标，不直接下单（信号-执行分离）；② 事件强类型 + 确定性编号（可回放/对账）；③ 成本与滑点作为可插拔组件（配置驱动、可单测）。

## 5.3 向量化/研究型框架对照

| 系统 | 特征 | 借鉴结论（当前） |
|---|---|---|
| **VectorBT** | 全向量化、参数扫描极快 | **部分采纳**：参数扫描（网格 + 进程池）+ 指标向量化实现；**未采纳**：把向量化结果当**结论**（A 股约束在向量化里表达不可靠） |
| **Backtesting.py** | 极简 API、上手快 | **采纳**：策略基类极简面；**未采纳**：其撮合简化（无 A 股约束层） |
| **bt（Philippe Morissette）** | 组合树 + 权重再平衡 | **采纳**：目标权重驱动的再平衡语义；**未采纳**：组合树（本项目为单账户、单策略） |

### 向量化类借鉴结论

**采纳**：向量化只用于**筛选/校验**（参数扫描、数据不变量校验的向量化实现）。
**未采纳**：向量化回测作为结论来源——理由：T+1 可卖数量、涨跌停排队、停牌在事后修正层里难以穷尽验证。

## 5.4 数据与存储技术对照

| 技术 | 特征 | 借鉴结论（当前） |
|---|---|---|
| **Parquet（列式）** | 压缩率高、列裁剪、谓词下推 | **采纳**：主库直读（只读）；年分区布局；`filters` 下推（子集宇宙免扫全市场）→ `btf.data.parquet_reader` / `core.YearTableStore` |
| **DuckDB** | 嵌入式分析查询 | **未采纳（保留评估）**：当前规模下 PyArrow 分组/连接已够；引入即引入第二套 SQL 口径 |
| **JSONL** | 行式、可追加、可 diff | **采纳**：事件/成交/拒单/快照落盘格式 |
| **SQLite/服务型库** | 事务、并发 | **未采纳**：单人单机、产物以"可审计文件"为优先 |

### 数据存储类借鉴结论

**采纳**：① 列式存储 + 谓词下推（性能与内存的关键）；② 产物用**纯文本可 diff**格式（可信度 > 读写效率）；③ 内容指纹（`sha256`）作为数据版本锚点。

## 5.5 实验与可复现工具对照

| 系统/工具 | 特征 | 借鉴结论（当前） |
|---|---|---|
| **MLflow / W&B** | 实验跟踪服务 | **未采纳**：需服务端；改用 `local_jsonl` RunStore + `manifest` 四版本（可 diff、可 audit） |
| **DVC** | 数据版本控制 | **部分采纳理念**：内容指纹（不引入 DVC 工作流）→ `btf/data/version.py`（`meta`/`fast`/`full` 三档） |
| **Git** | 代码版本 | **采纳**：代码版本进 manifest；**1.0.0 定版 + 定版日冷备已执行；1.1.0 CLI 收编（2026-09-30）**；私有库 push 为老大动作（就绪待执行） |
| **pytest-benchmark** | 性能基准回归 | **采纳**：L5 基准（B1–B4 + perf），门槛双档（软目标/硬门槛） |

## 5.6 计算与调度技术对照

| 技术 | 特征 | 借鉴结论（当前） |
|---|---|---|
| **多进程（ProcessPool）** | 绕开 GIL、进程隔离 | **采纳**：参数扫描（含 initializer 预热跨组合共享数据源） |
| **多线程（ThreadPool）** | 共享内存、IO 等待时可并行 | **采纳（限定场景）**：pyarrow 释放 GIL 的逐年预计算（共享 store 加锁、IO 在锁外） |
| **Dask/Spark/分布式** | 大规模并行 | **未采纳**：日线单机规模不需要（NG4） |
| **Airflow/调度器** | 任务编排 | **未采纳**：人工/CLI 驱动即可；采集侧流水线独立 |

### 计算调度类借鉴结论

**采纳**：单进程事件循环保证确定性 + 进程池承担并行；**并对新增"每次装配都要付的"开销建立纪律**（披露类计算一律推迟到落盘路径）。

## 5.7 总借鉴结论矩阵

| 借鉴来源 | 采纳的机制 | 在 btf 的落地 |
|---|---|---|
| LEAN | 事件驱动分层 + 成本模型化 | `btf.engine` / `btf.execution` |
| NautilusTrader | 强类型事件 + 确定性标识 | `btf.domain.events` / 订单号 `O%08d` |
| Backtrader | 极简策略回调面 | `btf.strategy.base.StrategyBase` |
| QSTrader / bt | 目标仓位 + 再平衡职责独立 | `rebalancer` 插件（`full`/`threshold`） |
| VectorBT / Backtesting.py | 向量化用于筛选与校验 | `grid_search` + `quality` 向量化实现 |
| Parquet / pyarrow | 列式 + 谓词下推 | `parquet_reader` + `YearTableStore` |
| DVC（理念） | 内容指纹 | `data/version.py`（`meta`/`fast`/`full`） |
| MLflow（对照） | 四版本锁定（自研轻量版） | `manifest.json` + `local_jsonl` |
| pytest-benchmark | 性能基准回归 | B1–B4 + LIQ，双档门槛 |
| 未采纳清单 | W&B/DuckDB/SQLite/分布式/调度器/实盘通道/在线仪表盘 | 见 §5.3–§5.6 各行"未采纳"理由 |
