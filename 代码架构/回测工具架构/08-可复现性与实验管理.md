# 08 可复现性与实验管理

> **本文档描述 btf 的可复现机制与实验管理现状**——对应实现版本 **btf 1.3.4（2026-10-14 发版：L2 治理批 HH-1~HH-6——排序口径留痕＋A5/A6 例行对照＋adhoc 收编）**（沿革：1.0.0 定版 2026-09-29 → 1.1.0 CLI 收编 2026-09-30 → 1.2.0 配股/缩股入链路落版 2026-10-07 → 1.2.1 工具完备版 → 1.2.2 完备收口版 → **1.2.3 公司行动扩维＋收口五轮（V1.2.3 定版，2026-10-09）** → **1.2.4＝定版后 L4 阶段六单并入（R57′~R62′，2026-10-10 发版）**：R57′（`optimize --objective` 基准同源）／`walk-forward` 预热修复（R58′）／`lookback_bars` 声明（R59′）／**文档守卫 4 组＋纪律九**（R60′）／**折算感知 FIFO**（R61′）／**消费侧价格视图 `run.price_view`（默认 qfq）**（R62′）→ **1.3.1＝与 mdf 统一版本号（2026-10-11，无功能变更）**；口径以本文档正文为准）。
> 关联：数据指纹口径见 [05 §20.3](05-数据架构与数据集体系.md)；产物字段见 [04 §8.2.8](04-领域模型与核心接口.md)；验收见 [16](16-架构评审与验收标准.md)。

## 13.1 可复现性的三级定义

| 级别 | 定义 | btf 现状 |
|---|---|---|
| **L1 逐位一致（bitwise）** | 同机器、同进程产物，`metrics_digest` 逐位相同 | ✅ 已保证（确定性赋号、确定性顺序、原子写） |
| **L2 契约级一致** | 同四版本（数据/代码/配置/环境）+ 同规则版本 → 指标在浮点容差内一致 | ✅ 已保证：`bt verify` 双对账（recompute/stored） |
| **L3 语义一致** | 数据/规则升级后，行为变更**范围受控且可解释**（diff 报告） | ◐ 工具在位（digest/指标 diff + 事件流可读），"变更范围报告"仍为人工对照 |

**当前不承诺**：跨平台/跨 Python 小版本的浮点逐位一致（Windows 单机为唯一目标环境）。

## 13.2 四版本锁定 + 规则版本（RunManifest）

`manifest.json` 是运行现场的唯一权威记录（`btf/experiment/manifest.py::RunManifest`）：

| 字段 | 含义 | 来源 |
|---|---|---|
| `run_id` | `%Y%m%d_%H%M%S_<config_hash 前 6 位>` | 创建期生成 |
| `status` | `RUNNING` / `COMPLETED` / `FAILED` | 生命周期流转 |
| `contract_version` | 运行结果数据契约（`runresult.v1`） | 常量 |
| `btf_contract_version` | 插件/领域契约（`1.0`） | `domain.contracts` |
| `data_version` | **数据指纹**（`content_hash` + 逐表明细 + `mode` + `anchor_date`） | 落盘路径实算 |
| `code_version` | `package_version` + Python 版本 + 平台 | 运行时 |
| `config_hash` / `config_effective` | 配置哈希 / **生效配置**（脱敏） | 配置合并层 |
| `env_version` | 环境版本标识 | 运行时 |
| `rules_version` / `rules_overrides` | 规则源版本 / 显式覆盖项 | RulesProvider |
| `seed` | 随机种子（`seed.master` 单源 → 派生） | 配置 |
| `metrics_digest` | 指标摘要（对账基准） | 落盘期计算 |
| `error` / `assembly_notes` | 失败原因 / 装配期说明（降级、披露项） | 生命周期 |

**主版本校验**：`RunManifest.from_dict` 遇到不兼容主版本 **拒绝解析**（不静默错值）。

## 13.3 RunStore 产物目录契约

```
回测产物/runs/<run_id>/
├── manifest.json              # 运行现场（四版本 + 摘要 + 说明）
├── metrics.json               # {"contract_version": …, "metrics": {…}}（不可算项 = null）
├── snapshots.jsonl            # 逐日 SessionEnd 快照（净值曲线来源）
├── trades.jsonl               # 交易（按标的聚合口径）
├── fills.jsonl                # 逐笔成交（含费用、撮合序号）
├── rejections.jsonl           # 拒单（RejectCode + message，风控拒绝含规则名）
├── events.jsonl               # 事件流（可采样；采样时含哨兵行 kind="_sampled"）
├── data_quality_report.json   # 数据不变量校验报告（dataquality.v1）
└── report.html                # HTML 报告（6 章；由 bt report 可再生成，幂等）
```

**写入纪律**：先 `create_run` 建骨架（失败也有现场）→ 流式追加 JSONL → `metrics.json` 原子写 → manifest 状态置 `COMPLETED`；
异常路径 `mark_failed(reason)` 后抛出。所有落盘走 `atomic_write_text(..., fsync=True)`（文件 + 目录项）。

## 13.4 随机种子管理

- 配置级：`seed.master`（单一真源）→ 运行期派生各组件种子（策略/采样/扰动）。
- 纪律：**任何随机行为必须来自派生种子**，禁止 `random` 无种子调用；采样类功能（如事件日志抽样）记录是否采样。

## 13.5 数据版本消费（与 [05 §20.3](05-数据架构与数据集体系.md) 呼应）

| 机制 | 说明 |
|---|---|
| 公司行动清单来源哈希（1.2.0，CL-2 R2′） | `corp_actions.json` 记录 akshare 快照 `snapshot_sha256`＋统计 ⇒ 「这份清单锚在哪份源」可复核；正推校验不一致 ⇒ 挂起披露（禁造数） |
| 数据冻结清单（1.2.0，CL-4/S-2） | `bt dataset freeze` → `<项目>/_freeze/<anchor_date>.json`：`anchor_date`＋表清单（行数/日期域）＋`content_hash`（BB-1 同源实算）；同锚复冻**幂等**、哈希不同**显式冲突**；只读、不改 RC-14 门禁语义 |
| ETF/LOF 分红与折算源（1.2.3，CL-2-H／ADR-20） | 分红源 **`fund_div`（第 20 表）**——只消费 `div_proc='实施'`、按 `(ts_code, ex_date)` 去重、回退链披露；折算源 **`fund_adj` × `pre_close` 双证据**（禁止用 `fund_share` 判折算）；专项扫描 `bt data scan-consolidation`（结果 JSON 落盘；退出码 0/1/2） |
| **价格视图入产物（1.2.4，R62′/N64）** | `run.price_view`（缺省 `adjusted`）进 `manifest.config_effective` ⇒ **config_hash 与 R1 复现口径随视图**；跨 `price_view` 的 run **数字不可直接比较**（复现/对比前先核对视图） |
| 计算时机 | **仅落盘路径**（`run(persist=True)`）；`persist=False`（网格组合/内存回测）**零成本**；进程内 memo 同输入只算一次 |
| 档位 | `meta`（缺省，Parquet 元数据，毫秒级）/ `fast`（键列抽样）/ `full`（全列抽样，可检数值级修订） |
| 表集 | 按**本次实际使用**的表（宇宙 `daily_table_of` + 状态/身份表 + 基准表） |
| 区间 | `years=` 只覆盖区间涉及年份 |
| 锚点 | `anchor_date` = 数据水位（最大日期）**裁剪到区间末** |
| fail-closed | 计算失败即抛，**绝不**回落 `sha256:unknown`；内存 Feed 显式标 `sha256:in-memory:Nsym` |
| 变异性检查 | 键列变更 / 数值级修订（`full`）/ 文件重写（`meta`）三类变更**均须改变指纹**（有断言） |

**✅ RC-14 已交付（2026-10-05）：版本门禁（声明 → 运行前校验）**——
`data.dataset.{version,expected_hash,anchor_date}` 成为 **schema 可达**的声明键（原 `version` 死键/顶层键不可达已修）；
装配期 `component_assembler.guard_dataset_version`：声明哈希 ⇒ 实算 `content_hash`（档位 = `data.fingerprint_mode`）**严格相等**比对，
不一致即 `ConfigError`（附两端哈希）；声明 `anchor_date` ⇒ 实算水位（未裁剪）必须 ≥ 声明；内存 Feed 声明任何版本键 ⇒ 拒（无法校验，**拒绝静默放行**）；
通过则记装配披露（声明 vs 实算 + 档位）。**未声明 ⇒ 零成本**（不计算、不披露——网格路径不受影响）。
> 边界说明（**CL-4，2026-10-06 更新**）：**不可变快照（冻结副本）已立项并落地**——
> `bt dataset freeze`（**S-2：清单 ＋ 哈希**，19 号 §72.5）落「表清单（名＋行数）＋ `content_hash`
> ＋ `anchor_date`」**只读清单**（默认 `代码\_freeze\<anchor_date>.json`；`BTFTOOL_FREEZE_DIR` 可覆盖）；
> `content_hash` 与 RC-14 门禁 / `manifest.data_version` **同源**（BB-1 实算 `data/version.py::compute`，
> 不另起哈希）；同 `anchor_date` 复冻**幂等**（哈希一致不覆写）/ **显式冲突**（哈希不同即报错）。
> ⇒ 门禁仍是「跑前声明 → 校验一致」，冻结清单是其**存档面**（**不改门禁语义**）。
> ⚠ **S-2 固有风险与有效边界（登记要求）**：只冻「清单 ＋ 哈希」，**依赖原始库不被改写**——
> 若 `D:\全量数据\market_data\` 的历史 parquet 被回填/重算，**旧清单不可自证**（哈希对不上，
> 且原始数据已非当时物）。因此：① **原始库变更必须留痕**（改历史须注明范围/时间/依据）；
> ② S-2 只对「**未被改写**」的窗口有效（召用纪律见 [20 号纪律四](20-回测平台使用指引.md)）。
> 声明键实位：`schemas/backtest.v1.json` → `data.dataset.{version,expected_hash,anchor_date}`；锚点见 [09 §14.10](09-测试验证与基准.md) #18。

## 13.6 状态快照与事件回放

- **快照**：逐日 `SessionEnd`（持仓明细 + 现金 + NAV）落 `snapshots.jsonl` → 净值/回撤/换手指标的唯一来源。
- **事件流**：`events.jsonl` 记录 7 类事件（含订单号与成交序号），可**回放校验**（`bt verify` 按产物重算指标）。
- **采样披露**：事件超预算时采样（`event_log_max_records`，缺省 500,000），采样状态写入 manifest 与报告——**采样即披露，不静默**。

## 13.7 幂等与重试

| 场景 | 机制 |
|---|---|
| 重跑同一配置 | 生成**新** `run_id`（不覆盖历史）；`bt verify` 可对两个 run 的 digest 做一致性对照 |
| 报告再生成 | `bt report --run <id>` **幂等**（同产物 → 同 HTML；覆盖写） |
| 失败恢复 | 失败 run 保留现场（`status=FAILED` + `error`）；**不做自动重试**（避免掩盖不确定性） |
| 半成品识别 | 目录存在但 `status=RUNNING` 且无更新 → 判定为未完成（工具按状态读取，不误当结果） |
| 并发写 | 不同 run 目录互不干扰；同 run 目录不允许并发写（单进程模型保证） |

## 13.8 实验查询与分析入口（当前）

```python
from btf.experiment.store import LocalRunStore

store = LocalRunStore()                  # 缺省 回测产物/runs（BTF_OUTPUT_DIR 可覆盖）
store.list_runs()                        # run_id 清单（名字序）
manifest = store.read_manifest(run_id)   # 四版本 + 摘要
metrics = store.read_metrics(run_id)     # 指标（不可算项 = nan，落盘 = null）
bundle = store.load(run_id)              # 全产物（报告再生成/对账入口）
```

```bash
bt verify --run <run_id>                 # digest 双对账（recompute vs stored）
bt report --run <run_id> --out out.html  # 报告再生成
```

**跨 run 聚合**：当前用脚本/Notebook 遍历 `list_runs()` + `read_manifest/read_metrics`；若未来需要聚合查询再评估 DuckDB（**不引入**数据库服务）。
