## 使用纪律（**首条 · 必读**）

> 本节是**全文档第一条**，优先级高于其后一切操作说明。
> 依据：19 号 §60 轮次十四审查；老大 **2026-10-05 Q3 裁决**「纪律类立即补、配置类留批次」。
> **纪律约束的是人，不依赖代码交付 ⇒ 即刻生效。**

### 纪律一 · btf 是记账机，不是裁判

btf 能证明的是「**这笔账算得对**」——撮合无前视、税费分段正确、复权恒等、幸存者偏差已处理、财报 PIT。
它**不能**证明「**这个策略有效**」。

| btf 能回答 | btf 不能回答 |
|---|---|
| 这笔成交的税算对了吗？ | 这个策略的 alpha 是真的吗？ |
| 这个区间的年化是多少？ | 这个年化在未来还能持续吗？ |
| 相对基准的超额是多少？ | 这个超额是否只是挑参数挑出来的？ |

**⇒ 任何策略结论，必须在框架外补 L4 推断（成本敏感性 / 置换检验 / DSR / Walk-Forward）之后，才可引用为"有效"。**
L4 推断层工具**已具备**（RC-06 `optimize` 报 N＋PSR/DSR · RC-07 `--perturb` · RC-15 `validate walk-forward` · RC-16 `validate mc/perm`，2026-10-06 全部交付）；**但「工具具备」≠「结论有效」**，仍须按纪律一 ~ 纪律三使用，因此——

### 纪律二 · 结论降级表述（**已复跑；2026-10-06 按 GG-2 更新**）

**在 RC-01 / RC-02 / RC-05 的成本敏感性复跑完成前**，所有"有超额 / 有 alpha"的表述
一律写作「**零摩擦假设下的记账结果**」，**不得**直接表述为策略有效。

理由（应用层 98 份 manifest 实证）：

- 滑点 **100% 为零**（98/98），成交量约束 **100% 未启用**（98/98）；
- 已计费用年化约 0.15%；**v77 同区间实测：滑点（价内）≈ 显性费用的 2.08 倍**（`final_nav` −11,217.87 元 vs `total_fees` +27.88 元；19 号 §65.5 / §67.3 N2）——**滑点仍是主导成本项**；
- v77 十年超额年化约 0.7% ⇒ **补滑点后 IR 0.0504 可能直接向 0 收敛**。

> **复跑结果（2026-10-06；RC-01/02/05 已交付）**：上述预警**基本坐实**——
> v77 同区间（2023-01-01~2026-09-23 / top_k=10 / 000300.SH）的超额**必须按口径分段陈述**：

| 口径 | 超额 | IR |
|---|---|---|
| 零摩擦（`slippage none` + VPP 关）＝**原"可采信结论"的口径** | **+7.19%** | **0.0504** |
| **交付默认**（0.1% 滑点 + 5% 参与率；`bt run` 未写 `execution.*` 时的实际口径） | **+6.07%** | **0.0305** |
| 压力（0.3% 滑点） | +4.28% | **−0.0013（转负）** |

- **禁止跨口径比较**；引用"v77 有超额"必须**同时给出所用口径**（三段细分与全矩阵见 19 号 §62.3①）；
- 位移 **≈1.12pp 全部来自口径**（零摩擦格逐位复现原声明值 ⇒ **引擎零漂移**；双锚冻结值见 19 号 §63.2）；
- 本区间 VPP 5%→10% **零效应**（逐位一致）；
- 预警坐实：IR **0.0504 → 0.0305（−40%）**；0.3% 滑点下**风险调整后不成立**。

> 唯一例外：明确标注了"已补滑点/VPP 敏感性"的复跑结果，可按其实测口径表述
> ——**现已具备**（上表三段 + L4 三表：19 号 §62.3）。

### 纪律三 · 基准必须跑前定死，窗口不得事后挑选

- **基准（benchmark）在按下回车之前就要定死**，并在报告中原样披露；
- **禁止**跑完看哪个基准好看就用哪个。实证：v77 同一区间 vs300 超额 **+2.98% / IR −0.004**，vs905 超额 **+30.08% / IR +0.63** —— **同一策略结论符号相反**。
- **危机区间不得事后剔除**：2015 股灾 / 2018 熊 / 2020 疫情 / 2024 初流动性冲击，必须**跑前声明**是否纳入，跑后不得因难看而切掉。
- **危机窗清单可配置**（RC-13）：内置 5 窗（2015 股灾 / 2018 熊 / 2020 疫情 / 2022 / 2024 初冲击，**月级**），
  可经 `analysis.crisis_windows` **覆盖**（声明后替换内置表）；回测区间与危机窗**重叠时装配期强制披露**（`assembly_notes`）
  —— 只披露、不改数 ⇒「跨危机 / 跨平静期」结论**不可直接对比**。
- 多组参数 / 多区间网格选优（如 l2-ablation 的 7 臂 × 5 区间 × 2 基准 = 70 单元格）**裸挑最优无效**，
  须报告**试验总数 N** 并做多重检验校正（RC-06/08/09 **已交付**，由工具自动给出）。

### 纪律四 · 数据冻结、未建模公司行动与退市清算口径（**2026-10-06 新增**；CL-2/CL-3/CL-4）

- **数据冻结（CL-4 / 19 号 §72.5 S-2）**：引用结论时建议连同**冻结清单**（`bt dataset freeze`，
  `anchor_date` ＋ `content_hash`）——① ⚠ S-2 **只对「未被改写」的窗口有效**：`D:\全量数据\market_data\`
  的历史 parquet **一旦回填/重算，旧清单不可自证**；② 因此**改动历史数据必须留痕**（范围/时间/依据），
  否则"这份结论锚在哪份数据"无法复核；③ 冻结清单**只读**、同 `anchor_date` 复冻幂等/冲突显式
  （不静默覆写）；④ 清单**不改变** RC-14 门禁语义（门禁＝跑前声明→校验一致）。
- **配股 / 缩股（CL-2 第二段后现状；R8′/R9′/R18′ 更新）**：**配股已建模**（离线清单正推校验，
  **165 条**；挂起 **11 条**附股本级披露 `r_effective`/认购率/`forward_err_eff`——**仅披露不建模**，
  N19）；**缩股经股本级确证全区间仅 1 例**（`000887.SZ 2007-03-30`，比例 0.32665——三重证据：
  股本/复权因子/价格一致）**且已建模**（`consolidations_confirmed`，R18′）；**其余代理候选无股本
  佐证 ⇒ 只披露**（N17/§85.2：价格代理只配做候选生成，判定走股本 × 因子交叉）。⇒ 引用相关结论
  时的保留表述：「**配股按 Q-4(a) 默认全额行权建模**，与真实股东行为可能存在偏差；**缩股按股本级
  确证建模（全区间 1 例），代理候选仅披露**」（命中配股/缩股标的的 run 结论**继续带口径保留**）。
- **公司行动覆盖段（报告披露字段清单；DOC-12，2026-10-07；⏳ 目标态——R25′/R36′）**：报告「假设与披露」
  须含 **6 项字段**——`命中分红笔数` ／ `命中折算次数` ／ `未建模项清单` ／ `指标口径（名义价｜hfq）` ／
  `记账口径（现金｜再投）` ／ `告警列表`；宇宙含 ETF/LOF 且区间**跨越折算日/除息日**时**必须**出现
  「**本 run 策略信号基于名义价，存在跳变失真**」告警（ADR-20 第 8/9 条；Q-9=(a′) 已裁：指标保持
  名义价、记账补齐公司行动、现金到账为默认——19 号 §94）。字段以产物 `assembly_notes` ＋报告节形式落盘（R36′）。
- **退市清算口径（CL-3 / 19 号 §72.4）**：默认 `carry`——残值按**区间内末次可用收盘价**携带、
  **未清算**（NAV 不含退市清算损益；与历史口径**逐位一致**）；压力档 `--delisted-settlement writeoff`
  ＝区间末按 **0 核销**（全额损失）。⇒ 引用退市标的相关的净值结论时**必须标注所用口径**；
  两档差异**只出现在 writeoff**（防前视：核销/估值基准一律取 ≤ 区间末的末次收盘，不取区间外价）。

### 纪律五 · 长区间 run 的单点终值不可作结论依据（**2026-10-07 新增**；N20／R14′）

- **路径混沌实测**（19 号 §82.3）：5,040 交易日的消融 run 对 **≤0.3%** 的除权建模扰动，
  终值差被放大至 **−5%~−98pp（约 33 倍）且符号可反转**（7 run 实测 +0.21pp～−98.05pp）——
  路径依赖策略下「终值差」由混沌主导，**符号与量级均不可预测**。
- ⇒ **5,040 日消融类长区间 run 的单点终值不得作为结论依据**；修复/回归的判定下沉到
  「**首次分歧日 ＋ 当日分解（股数/现金/NAV Δ＝M×(P−Pr)）＋ `n_fills` 差**」层
  （对账产物 `r7p_divergence.json` 的 `divergence` 字段）。
- **v77 主口径（904 日）不受影响**：三档未命中任何配股 ⇒ 逐位一致
  （+7.19%／+6.07%／+4.28% 对外表述不变）。
- ⚠ 历史口径更新：5,040 日消融 run 的**旧数值已被本轮改变**（−5%~−98pp）——凡引用过这些
  run 数值的历史文本须按 20 号纪律四加口径更新。

> **关于「完备」的定义（老大，2026-10-07；R20′/19 号 §85.4）**：**完备 = 除策略本身这一长期演进
> 项目外，工具部分不会因工具本身导致回测出现巨大问题**——判定单元是「工具缺陷是否会造出巨大
> 错误的回测结论」，而非「是否存在未实现功能」。据此：**N20 路径混沌属引用纪律**（回测固有属性，
> 非工具错）、**L4 推断层属策略长期演进**（定义明确排除；工具已齐、真实执行 0 次）。

## 0. 一句话看懂 btf

**btf（BT-Foundation）是 A 股量化回测工具**：你写一个**策略**（Python 类）+ 一份**配置**（YAML），
它按日循环跑完整个回测区间，产出**收益曲线 / 绩效指标 / HTML 报告**，并把结果落盘成**可复核的产物**
（含 manifest 摘要、逐日快照、成交明细）。核心思想是**「信号与执行分离」**——策略只负责说"我要什么组合"，
撮合、成本、滑点、风控、再平衡都由平台完成。

一次完整回测就四步：

```bash
bt config-check config.yaml     # ① 校验配置（合并 + Schema + 策略可加载）
bt run --config config.yaml     # ② 跑回测并落盘
bt report --run <run_id>        # ③ 由产物生成 HTML 报告
bt verify --run <run_id>        # ④ 复核：产物重算指标 vs 落盘摘要
```

## 3. 命令速查（12 命令）

| 命令 | 作用 | 关键参数 | 是否改产物 |
|---|---|---|---|
| `config-check` | 四层合并 + Schema 校验 + 脱敏摘要 | `<config.yaml>` `--dump` `--resolve-strategy` | 否 |
| `run` | 执行回测并落盘 | `--config` `--set K=V` `--dry-run` `--out` `--verbose` | 是（建 run 目录） |
| `report` | 由产物再生成 HTML 报告（幂等） | `--run` `--out` `--out-dir` | 写 report.html |
| `verify` | R1 复核：重算指标 vs manifest 摘要 | `--run` `--out-dir` | 否 |
| `test` | 跑 pytest 测试层 | `--layer` `--pattern` `--path` | 否 |
| `dataset` | 黄金集：构建 / 主库对账 / 内嵌重算 | `build-golden` `--verify` `--refcalc` | 视动作 |
| `optimize` | 参数网格搜索 | `--config` `--grid` `--objective` `--workers` `--top` | 是（多次 run） |
| `validate` | 滚动验证 / 蒙特卡洛（RC-15/16） | `walk-forward\|mc` `--config` `--window` `--test` `--step` `--mode` `--purge` `--embargo` `--run` `--n` `--seed` | `mc` 否；`walk-forward` **是**（每折落盘） |
| `check` | 十项架构门禁（提交前必跑） | 无参数 | 否 |
| `cold-backup` | 跨版本源码冷备 | `--reason` `--out` `--verify DIR` | 是（备份） |
| `runs` | 列历史 run 摘要（只读） | `--latest N` `--out-dir` | 否 |
| `show` | 单 run 的 manifest + 指标摘要（只读） | `--run` `--out-dir` | 否 |

> **`check` 与 `test` 的分工**：`check` = **提交前十项门禁**（lint / 架构契约 / 冒烟 / 预算 / 数据不变量 / 插件边界基线…，一体跑完）；`test` = 按测试层跑 pytest（`--layer l1~l5`）。日常改完策略/代码，先 `bt check`。
> **`show` 与 `verify` 的分工**：`show` 只打印落盘事实（快、不重算）；`verify` 会**重算指标并对账**（慢、验证一致性）。

## 4. 配置详解（config.yaml）

配置是**四层合并**：内置默认 → 用户 YAML → 环境变量（`BTF_*`）→ CLI `--set`。最终经 **JSON Schema** 校验。

### 4.1 完整示例

```yaml
schema_version: "backtest.v1"          # 固定值，契约版本

run:
  strategy: "examples.rotation:MonthlyMomentumRotation"   # module:Class
  params: {top_k: 5, lookback: 20}     # 策略构造参数（直注入）
  universe:                            # 标的宇宙（见 §6）
    source: "explicit"
    symbols: ["000001.SZ", "600519.SH", "600036.SH"]
  period: {start: "2020-01-01", end: "2022-12-31"}
  initial_cash: 1000000

data:
  feed: "tushare_parquet"              # 本地库（见 §5）

execution:
  handler: "next_open"                 # T 收盘决策 → T+1 开盘成交
  cost_model: "tiered_v1"              # A 股阶梯佣金
  slippage: {model: "none"}            # 无滑点（回测基线）

risk:
  rules: [{name: "max_weight", params: {max_weight: 0.4}},
          {name: "cash_check"}, {name: "tradability"}]

rules:                                 # 规则源（仅声明，不写参数字面量）
  source: "mirror_json"
  path: "D:/量化策略/赤潮/rules_mirror_v77.json"

seed: {master: 20260926}               # 随机种子（可复现）
report:
  sections: [summary, equity, drawdown, monthly_heat, trades, assumptions]
  benchmark: "000300.SH"               # 基准指数（装配期即校验格式+覆盖）
```

### 4.2 各段速查

| 段 | 必填 | 说明 |
|---|---|---|
| `schema_version` | ✅ | 固定 `"backtest.v1"` |
| `run.strategy` | ✅ | `module:Class` 点分路径（schema 正则禁止路径符） |
| `run.period` | ✅ | `start`/`end`（`YYYY-MM-DD`）；`anchor` 可选（对齐日） |
| `run.universe` | 可选 | 缺省按策略的 `universe` 声明；见 §6 |
| `run.initial_cash` | 可选 | 初始资金，> 0 |
| `data.feed` | ✅ | `tushare_parquet` / `mixed` / `memory` |
| `data.allow_degraded_limit` | 可选 | 允许区间早于涨跌停约束起点（默认 false，早于即报错） |
| `data.fingerprint_mode` | 可选 | 数据指纹档位 `meta`(默认)/`fast`/`full` |
| `data.quality` | 可选 | 数据不变量校验（`enabled`/`strict`/`max_symbols`） |
| `execution.*` | 可选 | handler/cost/slippage/rebalancer，见 §7 |
| `risk.rules` | 可选 | 风控规则链，见 §8 |
| `rules.source` | 可选 | `static` / `mirror_json`，见 §9 |
| `seed.master` | 可选 | 随机种子（缺省也有确定性默认） |
| `report.benchmark` | 可选 | 基准指数代码（`000300.SH` 格式），装配期即校验区间覆盖 |
| `analysis.*` | 可选 | 指标口径（`risk_free_rate`/`annualization_factor`/`metrics` 名字表）＋ **`analysis.crisis_windows` 危机窗覆盖**（RC-13；缺省 = 内置 5 窗，见 纪律三） |

> **改配置后先 `bt config-check`**——它能同时抓「Schema 不合法」和「策略类名拼错」（加 `--resolve-strategy`）两类错误，比直接 `run` 报错快得多。

| feed | 说明 | 适用 |
|---|---|---|
| `tushare_parquet` | 读本地库 `D:\全量数据\market_data`（按年 parquet） | **日常回测默认** |

## 6. 标的宇宙（run.universe）

三种 `source`：

| source | 说明 | 关键字段 |
|---|---|---|
| `explicit` | 显式标的清单 | `symbols: [...]` |
| `all` | 全市场 | — |
| `index` | 指数成分（月末快照、**PIT 无前视**） | `index: hs300/zz500/sz50` 或 `000300.SH` |

```yaml
run:
  universe:
    source: "index"
    index: "hs300"            # 别名，或直接写 000300.SH
    as_of: "2020-01-01"
    include_delisted: true    # 含退市股（避免幸存者偏差）
```

> 策略内用 `ctx.universe()` 拿当日可交易宇宙。另：策略**构造器**声明 `rules` / `liq_series` /
> `index_universe` 形参时，装配期会**自动注入**规则源 / LIQ 预计算序列 / 月度成分映射（见 §9）。

## 7. 执行与成本模型（execution）

| 插件点 | 可用值 | 说明 |
|---|---|---|
| `handler` | `next_open` | T 收盘决策 → **T+1 开盘**撮合（回测基线） |
| `handler_params.volume_participation` | `0.05`（**缺省**）/ `null` | 成交量参与率上限（**RC-02**）：成交 = `min(委托, vol × rate)`；显式 `null` 或空 dict = 不启用（回 v0.2 全成/全拒语义） |
| `cost_model` | `tiered_v1`（A 股阶梯佣金）/ `zero` / `flat_rate` | 交易成本 |
| `cost_model_params` | 可选 dict（构造参数） | **RC-05** 成本模型参数覆盖：`tiered_v1` → `commission_rate / commission_min / segments`（缺省：万 2.5 / 最低 5 元 / 内置分段表）；`flat_rate` → `commission_rate / min_commission / stamp_duty_rate / transfer_rate`；**`zero` 无参数**（传参被忽略 + warn，不静默） |
| `slippage.model` | `none`（对账基线）/ `fixed` / `pct`（**缺省**）/ `sqrt_impact` | 滑点（`sqrt_impact` 为 **RC-12** 规模相关冲击，须显式选择） |
| `slippage.params` | 随模型：`pct` → `{pct: 0.001}`（缺省单边 10bp）；`fixed` → `{amount: …}`；`sqrt_impact` → `{eta / sigma / impact_cap}` | 滑点参数；**非 `pct` 模型时缺省层残留的 `pct` 键会被自动剥离**（RC-01 深合并防护） |
| `rebalancer` | `full` / `threshold` | 组合再平衡方式 |

> **默认组合（2026-10-06 订正；RC-02 起）**：`bt run` **未写** `execution.slippage` /
> `handler_params` 时，实际生效 = `next_open` + `tiered_v1` + **`pct 0.001`（单边 10bp）** +
> **`volume_participation 0.05`**。「零滑点」**不再是默认**，要它必须**显式声明**：
> `slippage: {model: "none"}` + `handler_params: {volume_participation: null}`
> （= **零摩擦对账口径**；双锚冻结值见 19 号 §63.2）。
> **跨 run / 跨口径对比必须显式写全 `execution.*` 成本段**——什么都不写，得到的是"交付默认"，不是旧基线。

> **成本参数覆盖示例（RC-05）**：
>
> ```yaml
> execution:
>   cost_model: "tiered_v1"
>   cost_model_params: {commission_rate: 0.0003, commission_min: 5.0}   # 覆盖券商佣金口径
> ```
>
> 亦可用 CLI 覆盖：`bt run <config> --set execution__cost_model_params__commission_rate=0.0005`
> （网格扫描同理可扫该键——成本敏感性分析的入口）。

## 8. 风控规则（risk.rules）

内置三条，按序执行：

| 规则 | 参数 | 作用 |
|---|---|---|
| `max_weight` | `max_weight`（或 `limit`） | 单标的上限 |
| `cash_check` | — | 现金约束（不超买） |
| `tradability` | — | 可交易性（停牌/涨跌停不成交） |

```yaml
risk:
  rules: [{name: "max_weight", params: {max_weight: 0.1}}, {name: "cash_check"}, {name: "tradability"}]
```

> **空链 fail-closed**：不写 `risk.rules` 且未显式 `allow_empty_chain: true` 时，装配期会报错——防止"忘了接风控"静默裸跑。

## 9. 规则源（rules）

规则参数**不写进 YAML**（H2 纪律：规则是单一真源，配置只声明"从哪读"）：

| source | 说明 |
|---|---|
| `static` | 非规则源策略（无外部规则） |
| `mirror_json` | 从 JSON 镜像读规则（`path` 指定，如赤潮的 `rules_mirror_v77.json`） |

```yaml
rules:
  source: "mirror_json"
  path: "D:/量化策略/赤潮/rules_mirror_v77.json"
  overrides: []            # 显式覆盖须逐条 {rule, param, value, override: true}
```

> 策略声明 `rules` / `liq_series` / `index_universe` 形参时，装配期会**自动注入**对应对象——策略里直接收参数用，不必自己读文件。

## 10. 策略编写

### 10.1 骨架：StrategyBase 三个钩子

```python
from btf.domain.contracts import CONTRACT_VERSION
from btf.strategy.base import StrategyBase

class MyStrategy(StrategyBase):
    contract_version = CONTRACT_VERSION      # 必须声明（未声明 → 装配期拒载）

    def __init__(self, param_a: int = 5, **_params):
        super().__init__()
        self.param_a = int(param_a)

    def init(self, ctx):                    # 回测开始前一次（预计算/缓存）
        pass

    def on_open(self, ctx, date):           # T 日开盘后（撮合已完成）
        pass

    def on_close(self, ctx, date):          # T 日收盘后（默认决策点）
        ...                                  # 产出目标组合
```

### 10.2 ctx API（策略唯一接口）

| 方法/属性 | 作用 |
|---|---|
| `ctx.universe()` | 当日可交易宇宙（`Instrument` 列表） |
| `ctx.bar(symbol)` | 当日 bar（停牌缺席 → None） |
| `ctx.history(symbol, end, n_bars=1)` | 截至 `end` 的最近 n 根 bar（升序）；**end > 当日 → 前视封堵报错** |
| `ctx.state(symbol)` | 当日状态面板（停牌/涨跌停/ST） |
| `ctx.portfolio` | 组合视图（`.cash` / `.positions` / `.total_value()` / `.position(symbol)`） |
| `ctx.current_date` | 当前交易日 |
| `ctx.submit_target(target)` | 提交**目标组合**（→ Rebalancer 转订单；每 on_close 至多一次生效） |
| `ctx.submit_order(order)` | 提交**显式订单**（细粒度路径） |

### 10.3 完整示例：月度动量轮动（等价于 examples/rotation.py）

```python
from btf.domain.contracts import CONTRACT_VERSION
from btf.strategy.base import StrategyBase
from btf.strategy.rebalance import TargetPortfolio

class MonthlyMomentumRotation(StrategyBase):
    contract_version = CONTRACT_VERSION

    def __init__(self, top_k: int = 10, lookback: int = 20):
        self.top_k, self.lookback = int(top_k), int(lookback)
        self._last_month = None

    def on_close(self, ctx, date):
        month = date.to_ymd()[:6]
        if month == self._last_month:          # 每月首个交易日调仓
            return
        self._last_month = month
        scores = {}
        for inst in ctx.universe():
            bars = ctx.history(inst.symbol, end=date, n_bars=self.lookback + 1)
            if len(bars) < 2:
                continue
            first, last = bars[0].close, bars[-1].close
            if first > 0:
                scores[inst.symbol] = last / first - 1.0
        if not scores:
            return
        ranked = sorted(scores, key=lambda s: -scores[s])[:self.top_k]
        w = 1.0 / len(ranked)
        ctx.submit_target(TargetPortfolio(date, {s: w for s in ranked}))
```

### 10.4 策略纪律（必须遵守）

- **只经 ctx 访问数据**（前视由 ctx 断言封堵）；
- **只产出 TargetPortfolio / Order**，不直接改持仓；
- **无 I/O**：策略层不 open 文件、不访问网络（可测性的前提）。

### 10.5 外部策略接入（项目外，零改动核心）

策略可放在 btf 项目之外，三步：

1. 写 `StrategyBase` 子类（**必须声明 `contract_version`**）；
2. 放进 import 路径：放到 btf 根下某个包，或 `set PYTHONPATH=D:\path\to\strategies`；
3. 配置引用：`run.strategy: "ext_strategy.ma_cross:MaCross"`，构造参数放 `run.params`。

## 11. 产物与报告

### 11.1 run 目录结构

```
回测产物/runs/<run_id>/
├── manifest.json              # 元数据：run_id/状态/配置哈希/数据指纹/规则版本/指标摘要/契约版本
├── metrics.json               # 全部绩效指标（15 项）
├── report.html                # HTML 报告（bt report 生成）
├── data_quality_report.json   # 数据不变量校验报告（若启用 data.quality）
├── snapshots/                 # 逐日快照（组合净值/持仓）
└── fills/                     # 成交明细
```

### 11.2 绩效指标（15 项）

`final_nav` / `total_return` / `annualized_return` / `annualized_volatility` / `sharpe_ratio` /
`max_drawdown` / `calmar_ratio` / `win_rate` / `profit_loss_ratio` / `n_fills` /
`total_fees` / `total_turnover` / `turnover_annualized` / `fee_ratio` / `n_trading_days`

> `run`/`runs` 的快速摘要只列 5 项（total_return / annualized_return / sharpe_ratio / max_drawdown / n_fills）；
> 全量 15 项在 `metrics.json`、`show` 全精度、报告里。

### 11.3 只读查询（不重算）

```bash
bt runs --latest 5          # 列出最近 5 个 run（run_id/状态/时间/5 指标）
bt show --run <run_id>      # 单个 run 的 manifest + 全精度指标
```

> `show` 对 FAILED 的 run 也能看（审计价值），只在 stderr 提示；`runs` 对坏 manifest **不静默**（行照列 + `[warn]` 写明原因）。

### 11.4 复核（verify）

```bash
bt verify --run <run_id>    # 重算指标 vs manifest.metrics_digest，输出「一致/不一致」
```

## 12. 参数调优（optimize）

网格搜索：对 `--grid` 指定的参数位做笛卡尔积，每组合一次回测，按 `--objective` 排名。

```bash
bt optimize --config config.yaml \
            --grid "run.params.top_k=3,5,10;run.params.lookback=10,20,40" \
            --objective sharpe_ratio --workers 8 --top 10
```

| 参数 | 说明 |
|---|---|
| `--grid` | `path=v1,v2;path2=v1,v2`（点分配置路径，值按 int→float→str 推断） |
| `--objective` | 排名指标（默认 `sharpe_ratio`） |
| `--workers` | 进程数（默认 8；`0` = 内联顺序，调试用） |
| `--top` | 打印前 N 名 |
| `--out` | 结果 JSON 输出路径 |

> ⚠ **极短区间告警**：区间太短时部分指标「数学有定义、业务无意义」（如 3 日的 information_ratio），`run` 会告警、`optimize` 排名会被污染——调参请用足够长的区间。**1.2.0 起 `optimize` 对 < 250 交易日的样本默认直接阻断（退出码 3）**，确需放行见 §4.7 `--allow-short`（21 号）。

## 14. 可复现性

btf 的「一次 run 可复现」由四件事保证：

| 机制 | 说明 |
|---|---|
| `seed.master` | 随机种子单一真源（一切随机经已播种 Generator） |
| 数据指纹 | `data.fingerprint_mode` 记录数据内容哈希（meta/fast/full） |
| `manifest.json` | 记录配置哈希、数据指纹、规则版本、契约版本、代码版本 |
| `bt verify` | 产物重算指标 vs manifest 摘要，抓「篡改/口径漂移」 |

> 复现一次 run：同一份 config + 同一数据指纹 + 同一代码版本 → `bt run` 应得到一致的 `metrics_digest`。

## 15. 常见问题（FAQ）

| 现象 | 排查 |
|---|---|
| `config-check` 报「策略不可加载」 | `run.strategy` 类名拼错 / 模块不在 `sys.path`（项目外策略用 `PYTHONPATH`） |
| 策略「未声明 contract_version」拒载 | 在策略类加 `contract_version = CONTRACT_VERSION` |
| 区间早于某年报错 | 涨跌停数据（`stk_limit`）起点约束；确认区间或 `allow_degraded_limit: true` |
| 空风控链报错 | 要么写 `risk.rules`，要么显式 `allow_empty_chain: true`（调试才用） |
| `optimize` 排名怪异 | 区间太短，部分指标业务无意义，换长区间 |
| 想知道时间花在哪 | `bt run --verbose`（分步耗时 + 数据质检 + 数据指纹） |
| 忘了 run_id | `bt runs --latest N` 找回 |
| 产物被改/口径漂移 | `bt verify --run <run_id>` 对账 |
