## 32.2 硬性要求对照（8 项）

| # | 硬性要求 | 落地 |
|---|---|---|
| 1 | 正确性优先 | 事件层唯一结论来源 + 黄金集 + 对账 + 数据不变量（见 [09](09-测试验证与基准.md)） |
| 2 | 扩展点插件化 | **10 注册点**（惰性装载、契约协商、`check_plugin_boundary` 守卫） |
| 3 | 配置声明式 + Schema 校验 | `backtest.v1`（未知键拒绝）+ 四层合并 + 脱敏 + `config_effective` 入 manifest |
| 4 | 入口多级、核心稳定 | CLI（7 命令）+ `btf.api` + Notebook；入口层不含编排（契约 10） |
| 5 | 入口只编排 | `btf.app` 单源编排；入口层与内层之间唯一出口 |
| 6 | 依赖方向铁律 | 10 契约机器守卫（[03 §7.3](03-总体架构方案对比与推荐.md)） |
| 7 | 可复现（四版本锁定） | `manifest.json` + 实算指纹 + digest 双对账 |
| 8 | 数据只读 | 主库只读；产物独立目录；`memory_map` 仅主库 |

## 32.4 复用与入口矩阵

| 入口 | 用途 | 与核心的关系 |
|---|---|---|
| CLI（`bt`） | 运维/回测/报告/对账/优化/测试 | 经 `btf.app` → `BTFRuntime`（不直连内层） |
| Python Facade（`btf.api`） | 脚本/自动化 | 与 CLI 同源实现 |
| Notebook + `btf.data` | 研究取数（只读） | 直用读取层（唯一 IO 入口） |
| `tools/*.py` | 门禁与机检 | 独立脚本（不属运行时包） |

## 32.5 评审机制（单人场景的"外部化"）

- **内部**：门禁 9 项 + 五层测试 + 变更留痕（CHANGELOG / 基线历史）。
- **外部独立审查**：由赤潮侧按轮次独立验收（只读 + 探针，不改 btf 代码），每轮产出问题清单与裁决；
  **完整的审查结论、裁决与执行留痕见 [19](19-架构审查与重构方案-20260927.md)**（含"独立验收 → 裁决 → 执行 → 回填台账"的闭环）。
- **不采信原则**：执行方声称的"已修复/已做过负向对照"须由审查方**独立复现**（本机制已实际拦下多起假绿/伪防线问题）。
