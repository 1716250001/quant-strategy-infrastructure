## 章 22 · 性能、容量与成本设计

### 22.1 现状实测基线

| 指标 | 实测值 | 说明 |
|---|---|---|
| 目录 / 文件 / 体积 / 行数 | 113 / 10,852 / **7,366 MB** / 291,396,574 | 全库（含 `metadata`） |
| 单文件均值 | ≈ 0.68 MB | 无小文件灾难（`by_year` 迁移的直接收益） |
| 体量 Top5 | `index_daily`(1,207 MB) · `moneyflow`(1,155 MB) · `daily_basic`(919 MB) · `wind_index`(535 MB) · `daily`(465 MB) | 合计约占全库 **58%** |
| 最大单年文件 | `index_daily` 单年 ≈ 35 MB | 与 ADR-5 的 `by_month` 阈值（2 GB）相距 57× |
| 日增 | < 30 MB [现状观测] | 年增 ≈ 8~11 GB [估算] |
| 日更规模 | `core` 7 表 + `extend` 34 表 | 17:30 起，并行度 **4**（`BACKFILL_PARALLEL_TARGETS`） |
| 并行上限 | 4 接口并发 | 与限频器预约制协同 |
| 写入模式 | **原子写**：`to_parquet(tmp)` → `os.replace` | 2026-09-30 引入（DB2），消除半写文件 |
| 迁移实测收益 | `moneyflow` 1 天/分 → **41 天/分** | 按年大表 + 整表重写路径（≈40×） |

### 22.2 性能设计要点（已服役机制）

| 机制 | 作用 | 失效时的表现 |
|---|---|---|
| 目录分区（`by_year` 为主流） | 缩小读写面；年文件整表重写避免行级随机写 | 小文件过多（`by_code` 表 158~5,851 文件） |
| 分页（`BACKFILL_PAGE_CONF` **18 表**） | 突破单次行数上限（实测 `us_basic` 24,256 行 = 5 页） | 静默截断（R13 断言守护） |
| 截断探测（`SUSPECT_CAPS`） | `n_rows == max_rows` 或命中特征值即告警 | 数据看似正常但缺尾部 |
| 并行 4 + 预约式限频 | 吞吐与配额的安全平衡 | 限频报错或额度耗尽 |
| 去重合并（`DB_AUDIT_PKEYS` **114** 键） | 幂等写，重跑零追加 | 重复行（体检 S4 = 0 判据） |
| 列裁剪（消费侧使用） | `daily_basic` 与 `daily` 行数同级但体积 **2×** → 收益显著 | 全列读取放大 IO |
| 布局无关读（`reader`） | 消费侧不感知布局变化 | 布局探测翻转 → 读空（R8/R9 守护） |

### 22.3 容量规划与压缩

| 项 | 现状 | 建议 |
|---|---|---|
| 压缩 | Parquet 默认（snappy）；**未显式指定 codec** [现状] | 保持默认；若体积压力出现，优先试 `zstd`（体积 −30%~50%，读略慢）[推断] |
| 目录布局 | `by_year` 70 · `single` 38 · `by_code` 1（刻意保留）· `mixed` 4（容器） | 不新增混合布局（INV-2） |
| Top5 表治理 | 占 58% 体积 | 分级冷备：Top5 季度冷备，其余半年 |
| 增长预估 | 年增 8~11 GB [估算] | 单表年增 > 500 MB → 触发 `by_month` 评估（ADR-5） |
| 快照占用 | 暂无（K2 上线后） | 关键表 30 天保留；超限降级为 digest（11 §21.4） |
| 归档 | 无 | 冷备即可；**不做删除**（历史不可再生是更高优先级） |

### 22.4 可靠性与单点（本章重点）

| 项 | 现状 | 风险 | 处置 |
|---|---|---|---|
| 磁盘 | **单盘单点**，无冗余 | R-1（物理损坏 = 全库丢失） | 冷备（独立介质）+ 重拉能力 + 频次建议：周 |
| 写入原子性 | `tmp + os.replace`；`by_year` 整文件重写 | 中断留下 `*.tmp`（可识别） | 已有；`tmp` 文件应被扫描排除 |
| 断点可靠性 | 三态 + 双校验（INV-3） | 断点与磁盘不一致 | `ckpt --show` 交叉核对 |
| 幂等 | 去重合并；**新建文件分支曾不判重**（已修 `_concat_pages` 去重） | 首次建库固化重复（实测 `us_basic` 1 行、`slb_len_mm` 34 行） | 修复已就位；建库后立即跑 `db-audit` 重复检查 |
| 半写防护 | 分页截断告警（`truncated=True`）+ 起点回验 | 分页缺页 | R13 |
| 恢复目标 | **RTO ≤ 24h**（含重拉）/ **RPO ≤ 1 交易日** | 无快照时 RPO 不可控 | PoC-2（08 §13.6） |
| SLO | 6 项（S1-S6，09 §14.10） | — | K3 每日打分 |

**结论**：本库的可靠性**不来自硬件**，来自"可重拉 + 幂等 + 可验证 + 原子写"四件套（03 §7.4）；**唯一的真单点是磁盘与凭据**（R-1/R-7）。

### 22.5 成本结构

| 成本项 | 现状 | 备注 |
|---|---|---|
| Tushare 授权 | 2000 积分档（年费） | 7 项漏网不为此升档（ADR-8） |

### 22.6 重估触发（与 07 §12.10 同源）

## 章 23 · 读侧一致性与消费契约

### 23.1 双分支读取层（ADR-6 展开）

| 维度 | 维护层 `common/reader.py` | 决策层 `赤潮/market_data.py` |
|---|---|---|
| 定位 | 库维护者/回测/体检 | 决策门面（线上 API ↔ 本地库） |
| 失败处理 | **fail-fast**（异常必须冒泡，严禁静默） | 可降级（线上失败→本地），但**必须披露来源与新鲜度** |
| 布局知识 | 无（布局不可知） | 无（经 reader） |
| 缓存 | 无 | `.cache/`（ROE 缓存等），不落主干 |
| 单位换算 | 不做（源口径直出） | 服务层显式换算（本节 23.3） |
| 契约 | 读侧 API 稳定（`read_code`/`read_range`/`list_codes`/`latest_date`） | 面向策略的字段级口径 |

**不统一的理由**（ADR-6）：两者失败语义相反；强行统一会得到"对外可降级 + 内部也静默"的最坏组合。

### 23.2 布局无关与时间口径

| 契约 | 规则 | 后果举例 |
|---|---|---|
| 布局不可知 | 消费侧禁止 `glob("by_year/*/[0-9]*.parquet")` 之类反推（INV-8） | 布局升级不致消费侧崩（`by_code → by_year` 迁移即先例） |
| 日期列 | 由 `TABLE_DATE_COL`（**79** 项）声明；查询统一 `YYYYMMDD` 字符串 | 防"年份被读成 int 又当字符串比" |
| 周/月频锚点 | 周锚点 = **该周周五**（非最后交易日）；`freq='W'` 会静默返空 | 误用 `last_trade` 静默漏 31 个长假周 |
| 月频格式 | `YYYYMM`（如 `broker_recommend`） | 跨频对齐需显式转换 |
| 排序 | 入库统一正序（源为倒序）；消费侧仍建议显式排序 | — |

### 23.3 单位与口径（消费侧最易踩坑处）

| 项 | 库内口径 | 陷阱 |
|---|---|---|
| `vol` | **手**（1 手 = 100 股） | 与"股"混用差 100× |
| `amount` | **千元**（`daily`/`fund_daily`/`cb_daily` 一致） | 曾为高危差异点，现已统一 |
| `total_mv`/`circ_mv` | **万元** | 与"元"混用差 1e4 |
| `total_share`/`float_share`/`free_share` | **万股** | 同上 |
| 价格 | **不复权**（库内只存不复权价 + `adj_factor`） | 复权须消费侧计算：`close × adj_factor / 最新 adj_factor` |
| 财务空值 | 非适用行业为空（`NaN`）；`pe` 亏损为空 | 使用前必须过滤（空 ≠ 0） |
| 行业/分类字段 | 空值含"不适用"语义 | 见 15 §27.4 |
| 汇率/货币 | `us_daily_qfq` 等为源币种 | 未做本币化 [现状] |

**消费侧纪律**：**换算只在服务层做一次并显式标注**；禁止"读出来顺手乘 100"。K1（列级契约机读化）落地后，`unit` 字段将成为断言（05 §20.4）。

### 23.4 只读隔离与写通道唯一（INV-4）

```
消费侧 ──只读──▶ reader / 决策门面 ──▶ 库           （不允许任何写）
维护侧 ──唯一写通道──▶ fetch/* + parquet_store ──▶ 库
```

| 违规形态 | 现状防线 |
|---|---|
| 消费脚本直接 `to_parquet` 覆盖 | 约定 + 代码审查；**无机器拦截** [风险 R-10] |
| 派生任务反向写主干 | INV-7；`market_state/custom_index/signals` 为白名单目录 |
| `alt_data` 写主库 | `assert_writable()` 硬拦 + violation 留证（10 §15.4） |
| 体检/工具误写 | 全链路只读或 dry-run（09 §14.1） |

### 23.5 影子数据与缓存版本

消费侧在库外做缓存（如决策侧 `.cache/` 的 ROE 缓存）时，**必须登记**：

| 字段 | 含义 |
|---|---|
| `source_db_version` | 缓存生成时的库版本号（`MD-YYYYMMDD.N`） |
| `source_tables` | 依赖的表清单 + 各表 `date_max` |
| `invalid_when` | 失效条件（如"下一交易日 18:00 后"或"依赖表 `date_max` 前进"） |
| `rebuild_cmd` | 重建命令（保证可复算） |

**纪律**：影子数据**不落主干目录**；报告/决策引用影子数据时必须标注来源与版本（否则视为 INV-10 违规）。

### 23.6 差距与改进

| 差距 | 风险 | 建议 |
|---|---|---|
| 无独立读侧契约测试 | 布局/语义漂移静默 | 三布局等价性测试（09 §14.12） |
| 单位靠文档与口头 | 跨表误用 | K1 列级 `unit` 断言 |
| 消费侧写入仅靠约定 | 误覆盖 | 只读挂载建议（10 §15.6） |
| 影子缓存版本未强制 | 结论不可复算 | 模板化 manifest（23.5） |

## 章 24 · 增量、分页与并发写建模

### 24.1 增量语义

| 概念 | 定义 | 载体 |
|---|---|---|
| 应更新日期集合 | 交易日历 ∩ 表有效区间（`start` ~ 上一交易日） | `trade_cal` + `BACKFILL_TARGETS.start` |
| 水位 | 已完成的最大日期 | 断点 JSON |
| 状态三态 | `done`（水位可信）/ `partial`（部分完成）/ `failed`（失败待重试） | 断点 JSON |
| 推进规则 | **先落盘成功，再推进断点**（INV-3） | `fetch/backfill.py` |
| 重跑语义 | 幂等：按主键去重合并，重复写不产生新行 | `merge_append`/`upsert_by_year` |

### 24.2 分页与截断（本库特有的"静默数据丢失"源）

**机制**：`BACKFILL_PAGE_CONF`（**18 张**）登记 `page_size × page_count`；`_concat_pages()` 全列去重（防翻页边界重复）。

| 危险点 | 事实 | 防线 |
|---|---|---|
| 单次上限静默截断 | `us_basic` 总量 24,256（6,000/页 = 5 页）；`fund_manager` 85,636；`slb_len_mm` 55,214；`index_member_all` 5,913 | R13 起点回验 + 多轮续拉 |
| 参数被忽略 | `fut_weekly_detail`/`new_share` 的 `trade_date` 被完全忽略（返回同一份数据） | 改 paged 全量拉取，不参与日更 |
| 返回上限特征值 | `SUSPECT_CAPS` 名单 | 命中即告警 + 分段重拉 |
| 首次建库固化重复 | 新建文件分支曾不判重（`us_basic` 1 行、`slb_len_mm` 34 行） | 已修 `drop_duplicates`；建库后必跑重复检查 |
| 页数触顶 | `truncated=True` | 告警"数据可能仍不完整" |

**建模结论**：分页的不确定性（页边界重复/截断/参数忽略）**无法靠"多拉一次"消除**，只能靠 **去重 + 回验 + 告警**三件套。

### 24.3 失败分类与重试/限频

| 错误类 | 判定 | 处置 | 实测教训 |
|---|---|---|---|
| 权限（无权限） | `_is_permission_error` | **1 次调用即停**，不重试；告警 + 替代路径 | 重试 5 次白等 18.5 秒（R15） |
| 限频 | 命中限频特征 | 等 `RateLimiter` 预约（不拥塞重试） | 预约制优先于退避 |
| 网络/超时 | 其他异常 | 指数退避，最多 `TS_MAX_RETRIES`=5 | — |
| 数据面（截断/空） | 行数与期望不符 | 分段/分页重拉 | — |

**限频配额（现状）**：daily 300/分（配置 250）、高频组 200/分（配置 170）、4 接口 1 次/小时、`index_global` 100 次/天；并行 4。

### 24.4 并发写建模（PoC-5 输入）

**现状假设：单写进程**（人跑 CLI 或调度触发，二者不重叠）。风险形态：

| 场景 | 后果 | 概率 |
|---|---|---|
| 两个 `gap-update` 同跑 | 同表整文件重写互相覆盖 → 后写者赢（丢先写的增量） | 低 [风险 R-4] |
| 日更与手工补数重叠 | 同上（`core` 表尤其危险） | 中 |
| 派生与主干同跑 | 派生读到半写状态 → **不可能**（原子写保证读到旧文件或新文件） | 已消除 |

**PoC-5 设计草案（最小实现）**：

```
写操作开始 → 尝试原子创建锁文件（含 pid + 时间 + 任务名）
  成功 → 执行；结束删除锁
  失败 → 若锁文件 pid 已不存在（进程崩溃残留）→ 自动接管并告警
                否则 → 拒绝启动并提示"另一写进程正在运行"
```

**验收**：① 第二进程被拒并给出明确提示 ② 崩溃后锁可自动失效（不产生"死锁无人能写"）（11 §21.1）。

### 24.5 恢复矩阵

| 中断点 | 状态 | 重跑行为 | 是否需人工 |
|---|---|---|---|
| 落盘前 | 断点未推进 | 全量重做该日 | 否 |
| 落盘后、记断点前 | 断点落后 | 重做后去重合并（等值） | 否 |
| 记断点后 | 完成 | 跳过 | 否 |
| 分页中途 | `partial` | 从断点日续做 → 回验起点 | 否 |
| 断点虚记（人为/异常） | 断点超前 | `ckpt --show` 抓出不一致 | **是**（先修断点） |
| 文件半写残留 `*.tmp` | — | 扫描排除并清理 | 否（自动识别） |

### 25.2 并列库硬隔离（INV-5 展开）

| 项 | 主库 | `alt_data` |
|---|---|---|
| 库根 | `D:\全量数据\market_data` | `D:\全量数据\alt_data` |
| 规格真源 | `config.py` | `config_alt.py` + `alt/spec.py` |
| 断点 | 主库断点 JSON | 独立断点 |
| 写保护 | 单写通道约定 | **`assert_writable()` 硬拦** + `_VIOLATION_LOG` |
| 与对方关系 | 对 alt 仅**只读联查** | 对主库只读 |

**联查契约（R14 覆盖）**：① 低匹配率必须告警（默认 `how='left'` 匹配率仅 3.3% 却"有输出不报错"）② 容差方向自动识别（参数顺序反了不报错）③ 列名错必须抛 `KeyError` ④ 日期列口径一致。

**为什么不合并**（ADR-10）：口径污染、授权混淆、断点体系冲突；且隔离**可观测性**优于"看起来统一"。

### 25.3 停更、替代与授权降级

| 类别 | 清单 | 处置 |
|---|---|---|
| 事实停更 | `gz_index`（止 2019-03-04）· `wind_index`（止 2026-09-21）· `stk_account`（止 2019-02-22）· 金十系海外宏观 14 张（源端停更 2025-08~10，标 `known_stale`） | 显式停更清单（GS-6），保留数据但标注；新鲜度豁免 |
| 授权漏网 | 7 项（10 §15.3） | 监控 + 替代 + 降级（ADR-8 / INV-9） |
| 替代完整性三档 | **完整**（`share_float`→akshare 五件套，细节更全）· **不完整**（`index_dailybasic`→乐咕月频；`fund_adj`→净值+分红自算）· **不成立**（`broker_recommend`→akshare 实测返空） | 每档给出可接受损失与决策影响 |
| 设计性缺口 | `DAILY_UPDATE_EXEMPT`（`freq=day` 但主动不日更） | 附原因 + 独立预算（09 §14.2） |

### 25.5 新源接入契约（防"接一半"）

```
① 规格登记（config/config_alt 任一处，不可两处）
```

## 章 26 · 数据治理、契约与血缘

### 26.1 消费者关系

| 消费者 | 关系 | 纪律 |
|---|---|---|
| 回测系统 btf | **只读** | 库变动不因回测需求而改主干口径；回测侧需要的派生在派生层做（04 §章 3） |
| 决策系统（赤潮） | 只读（经决策门面，可降级且披露来源） | 不写主干；影子缓存须登记版本（23.5） |
| 看板/报告 | 只读（经 JSON 契约） | 数字零手抄（ADR-12） |
| 研究/新需求 | 只读取切片 | 用 S-MIN~S-ALT 切片（05 §20.8） |

### 26.2 规格单一真源（INV-1 展开）

| 真源 | 内容 | 派生物 |
|---|---|---|
| `config.py` | 表规格（布局/模式/日期列/判重主键/缺口目标/限频/豁免） | CLI 行为、断点期望、体检判据、**文档字典**（K1） |
| 磁盘 | 实际文件与 Footer | 实测行数/体积（README 快照表，由脚本渲染） |
| `config_alt.py` + `alt/spec.py` | 并列库规格 | alt 体检与文档 |

**禁止**：任何第二处"表清单"（`gen_db_report` 曾硬编码接口清单并与 config 漂移，已修为从 config 派生——**这是 R-9 的历史实证**）。

### 26.3 显式豁免治理（INV-6 展开）

| 豁免类型 | 示例 | 要求 |
|---|---|---|
| 不日更但按周期更新 | 周期表（`freq != day`） | 声明周期与下次期望时间 |
| 设计性不更新 | `DAILY_UPDATE_EXEMPT` | 附**原因** + **复核日期** |
| 不建库 | X6（商品期货席位/库存等） | 记录理由与前提（价值低、存储翻倍） |
| 停更 | `gz_index`/`wind_index` | 从"缺口"移入"停更清单"，避免永久告警 |

**判据**：豁免必须**显式、有据、可复核**；"默认不拉"必须写成显式记录（否则与"漏登"无法区分——`fut_mapping` 事故即漏登）。

### 26.4 派生与血缘

**三层血缘**：源（Tushare/akshare/Wind）→ 主干表（113 目录）→ 派生表（`market_state` 等）。

| 血缘要素 | 现状 | 建议（K2/治理） |
|---|---|---|
| 表 → 源 | 由 `config.py` 模式隐含 | 字典中显式 `source` 字段 |
| 派生 → 输入表 | **未登记**（R-8） | 派生 manifest：输入表清单 + 各自 `date_max` + `db_version` |
| 派生 → 口径 | 分散在脚本注释 | 派生规格登记（单文件 README 或 spec） |
| 反向 | 禁止（INV-7） | — |

**派生幂等要求（INV-7）**：同输入必同输出；重建成本 ≤ 小时级；重建后 digest 一致（15 §27.3）。

### 26.5 变更治理（五类变更的流程）

| 变更类 | 例子 | 流程 |
|---|---|---|
| 加表/加目录 | 新增接口 | 25.5 六步 + 文档字典更新 + `regress` |
| 改布局/迁移 | `by_code → by_year` | 守恒校验（`rows_before − rows_after − dedup_removed == 0` 否则回滚）+ 迁移脚本登记 + 回滚方案 |
| 改列/schema | 新增财务字段 | K1：`schema_hash` diff 即登记 + 消费侧通知（09 §14.5） |
| 改口径 | 单位修正 | 视为**不兼容事件**：版本号 + 快照 + 通知；禁止静默改 |
| 改派生 | 信号逻辑 | 派生 manifest 记录输入版本；旧派生可重建复现 |

### 26.6 治理差距与改进

| 差距 | 风险 | 归属 |
|---|---|---|
| 派生输入版本未登记 | 结论不可复算（R-8） | §26.4 |
| 表→源映射隐含在代码 | 溯源需读码 | K1 字典增 `source` |
| 豁免复核无到期提醒 | 豁免长期化 | §26.3（复核日期入体检） |
| 变更登记靠人记 | 静默口径变更 | §26.5 + `db_version.json` |
