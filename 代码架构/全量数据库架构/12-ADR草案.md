## ADR-1 · 存储形态：单机 Parquet 数据湖，不引入数据库引擎

| 项 | 内容 |
|---|---|
| 状态 | **已服役**（现状即此形态） |
| 背景 | 全库 113 目录 / 10,852 文件 / 7,366 MB / 2.914 亿行；日增 < 30 MB；单机单用户；无并发写、无在线服务 |
| 决策 | 存储 = Parquet 文件 + 目录分区；**不引入** PostgreSQL / ClickHouse / DuckDB 服务化；不引入 Iceberg/Delta/Hudi 表格式与 metastore（02 §B11） |
| 备选 | ① 关系库单表存全部行情（否决：写入放大、无需事务）② 服务化列存（否决：7.4 GB 规模收益不抵运维成本）③ 表格式（否决：需服务端/重写全部落盘路径） |
| 理由 | 数据规模远小于任何引擎的收益门槛；现有"按年大表 + 去重合并"已解决小文件与更新语义；迁移风险 > 收益（01 §2.2 N2/N3） |
| 后果（正） | 零运维、零依赖、目录即分区（可读可复制可冷备）、读者无门槛 |
| 后果（负） | 不可行级更新（只能分区重写）；无事务/无并发保护（R-4）；无内建索引（全表扫描） |
| 复评触发 | 表数 > 200 或参与方 > 3 人；或出现"必须在线查询"的需求 |

## ADR-2 · 数据版本：轻量版本号 + 摘要指纹，不用表格式时间旅行

| 项 | 内容 |
|---|---|
| 状态 | **已定**（PoC-2/PoC-4 兑现） |
| 背景 | 覆盖写即不可回溯；消费侧偶发"要某日某表的原值"需求；无 Git/对象存储配套习惯 |
| 决策 | 版本号 `MD-YYYYMMDD.N` + `metadata/db_version.json`（变更表清单 + 快照指针）+ `rows/schema_hash/content_digest` 三件指纹（08 §13.4/§13.5） |
| 备选 | DVC（重、需 Git 习惯，采纳其摘要思想）；LakeFS（需服务端）；表格式（同 ADR-1） |
| 理由 | 版本信息只需"可解释变更 + 可比对"，不需要真时间旅行；摘要指纹的成本远低于全量哈希 |
| 后果（正） | 成本近零；`db_version` 可解释"当次所有行数变化" |
| 后果（负） | **不是真时间旅行**（不能按版本读任意表）；历史值依赖快照保留期 |
| 复评触发 | 回溯需求从"关键表"扩展到"全库逐日" |

## ADR-3 · 快照与回滚：旁挂 `_snapshots/`，不侵入主干路径

| 项 | 内容 |
|---|---|
| 状态 | **已定**（PoC-2） |
| 背景 | 现状无快照；误覆盖只能重拉（R-5）；主干路径被消费侧依赖，任何侵入都可能破坏读取契约 |
| 决策 | 快照存放于 `market_data/_snapshots/YYYY-MM-DD/`，**目录名由 `reader`/`list_codes` 明确排除**；内容 = 关键表 copy 或硬链接 + `manifest.json`（行数/schema_hash/digest）；回滚 4 步（08 §13.3） |
| 备选 | 表格式时间旅行（否）；全库逐日快照（成本高，先做关键表）；仅在冷备做（恢复粒度太粗） |
| 理由 | 主干零改动 = 零回归风险；manifest 让"回滚是否正确"可机检（而非靠感觉） |
| 后果（正） | 单表回滚 ≤ 5 min；回滚可验收（`db-audit` 与 manifest 完全一致） |
| 后果（负） | 占用额外磁盘；需保留策略（建议 30 天）；`_snapshots/` 必须被所有扫描排除（漏排除即污染布局断言） |
| 复评触发 | 出现误覆盖事故（立即升级为高优先）；或快照体积不可接受（降级为 digest 指纹） |

## ADR-4 · 主干只存观测值，不做策略语义

| 项 | 内容 |
|---|---|
| 状态 | **已服役**（写入纪律） |
| 背景 | 库同时服务回测/决策/看板/研究；若把信号、因子、指标算进主干，口径变更将不可逆地污染历史 |
| 决策 | 主干（raw/normalized）**只存源方观测值**；派生层（`market_state`/`custom_index`/`signals`）承载计算物，且**只读主干、可全量重建**。表达式与指标在消费侧计算（qlib 借鉴，02 §B8） |
| 备选 | 库内预计算因子/信号（否决：语义随时间漂移，无法回溯"当时用什么口径算的"） |
| 理由 | 观测值是对源的忠实映射，可验证；派生值随时可重算，不必回溯 |
| 后果（正） | 主干稳定、口径唯一、可复算；派生失败不影响主干 |
| 后果（负） | 消费侧需自行计算（重复劳动）；派生结果必须声明输入表清单（R-8） |
| 复评触发 | 出现"多个消费方重复实现同一派生"且口径开始漂移 |

## ADR-5 · 分区键不可变：布局由单一真源判定

| 项 | 内容 |
|---|---|
| 状态 | **已服役** |
| 背景 | 历史上 `by_code` 表被误按年写入 → 布局探测翻转 → `read_code` 恒空、`list_codes` 返回 `["2026", ...]`（静默灾难） |
| 决策 | 布局仅由 `fetch/backfill_io.py::table_storage_layout(table, mode, layout)` 判定；**任何调用方不得自行拼接年度路径**；`upsert_grouped` 硬拦按年目录（`LayoutGuardError`） |
| 备选 | 由调用方自行决定路径（否决：必然漂移）；不设守卫靠代码审查（否决：已证明失效） |
| 理由 | "两个本该联动的结构各管一摊"是本库最主要的静默失效模式（已复发 4 次，09 §14.4） |
| 后果（正） | 布局与规格永不分歧；R8/R9 断言可直接机检 |
| 后果（负） | 新增布局须同时改判定函数 + `reader` 适配 + 迁移函数（有意为之的摩擦） |
| 复评触发 | 单年文件 > 2 GB 或年增 > 500 MB/表 → 评估 `by_month`（11 §16.3） |

## ADR-6 · 读写分离：双分支读取层，且**不统一**

| 项 | 内容 |
|---|---|
| 状态 | **已服役** |
| 背景 | 维护层要"纯本地、异常必须冒泡"（静默会让断点记错）；决策层要"线上失败落本地并降级"（可用性优先）。两者语义冲突 |
| 决策 | 保留双分支：`common/reader.py`（维护层，fail-fast，布局不可知）与 `赤潮/market_data.py`（决策层门面，线上 API ↔ 本地库，可降级且**必须披露来源与新鲜度**） |
| 备选 | 统一为一套（否决：合并必然牺牲一方的语义，且破坏降级能力，01 §2.2 N7） |
| 理由 | 两者的失败处理要求相反；统一会造出"对外可降级但内部也静默"的最坏组合 |
| 后果（正） | 各自语义清晰；维护层可靠性不被降级逻辑污染 |
| 后果（负） | 两套代码需保持口径一致（跨层一致性测试，14 §23）；新人易混用 |
| 复评触发 | 出现"两套读取层结果不一致且无人发现" |

## ADR-7 · 写侧可靠性：断点三态 + 落盘先于记断点

| 项 | 内容 |
|---|---|
| 状态 | **已服役** |
| 背景 | 单机单盘无冗余（R-1）；断点若与磁盘不一致，会产生"以为有/其实没有"或"重复拉取" |
| 决策 | ① 断点状态三态（`done`/`partial`/`failed`）② **先落盘成功、再推进断点** ③ 断点与磁盘**双校验**（`ckpt --show`）④ 幂等落盘（按 `DB_AUDIT_PKEYS` 去重合并）⑤ 失败必须可见（不得静默） |
| 备选 | 依赖硬件冗余/事务（不可得）；断点仅记日期不记行数（否决：无法双校验） |
| 理由 | **可靠性由"可重拉 + 幂等 + 可验证"提供，而非由硬件提供**（03 §7.4） |
| 后果（正） | 任意中断后重跑安全；断点可信 |
| 后果（负） | 每次落盘多一次去重合并开销（可接受）；`partial` 表需要额外处理逻辑 |
| 复评触发 | 出现并发写（→ PoC-5 写锁） |

## ADR-8 · 漏网接口：监控 + 降级 + 替代源，**不升档**

| 项 | 内容 |
|---|---|
| 状态 | **已定**（机制已服役，替代源待补全） |
| 背景 | 7 项漏网接口（10 §15.3）官方门槛高于本档但实测可调，**状态随时可变**；收紧表现为静默断裂 |
| 决策 | ① 三处消费同一份 `LEAKY_PERMISSIONS` 清单 ② 无权限错误不重试 + 立即告警（收紧当天可知）③ 逐接口登记替代路径与**完整性标注**（完整/不完整/不成立）④ 依赖这些接口的方案必须给出降级路径（INV-9）；⑤ 不为此升档 |
| 备选 | 升档消除依赖（否决：成本与收益不匹配，且升档后仍有条款风险）；忽略（否决：静默断裂） |
| 理由 | 授权是外部变量，可控的是**发现速度**与**降级能力** |
| 后果（正） | 断裂可见、影响面可知；无额外授权成本 |
| 后果（负） | `index_dailybasic`/`fund_adj`/`broker_recommend` 替代**不完整或不成立** → 仍存在实质依赖（R-2） |
| 复评触发 | 任一 `monitor=True` 接口连续 3 交易日被拒且替代不完整 → 重新评估升档成本 |

## ADR-9 · 列级契约机读化（`config.py` 为真源）

| 项 | 内容 |
|---|---|
| 状态 | **草案**（PoC-1 后定） |
| 背景 | 现状 `db-schema` 只导出表名/布局/文件数/行数/大小/列名/日期范围；列类型、单位、可空、枚举靠文档与口头约定（05 §20.4） |
| 决策 | 列级契约（`dtype`/`unit`/`nullable`/`enum`）写入 `config.py` 规格（唯一真源）→ `db-schema --json` 导出 → ① 生成文档 ② 落盘前断言 ③ `schema_hash` 变更即登记（09 §14.5） |
| 备选 | 独立 `schema.yml`（dbt 式；否决：真源分裂为两处）；只在文档维护（否决：不可机检） |
| 理由 | "关联条目必须同处"是 `config.py` 不拆分的核心理由（regress R11 注释）；列级契约与取数规格同属表规格 |
| 后果（正） | 文档零漂移（R-9 消除）；列级缺陷在落盘前被拦 |
| 后果（负） | `config.py` 体积进一步增长（有意接受）；首次补全 113 目录的列级字段工作量可观（建议先做关键 20 表） |
| 复评触发 | PoC-1 实测维护成本过高 → 降级为"仅关键表列级契约" |

## ADR-10 · 并列库硬隔离：`alt_data` 独立成库，不合并主备

| 项 | 内容 |
|---|---|
| 状态 | **已服役** |
| 背景 | akshare 备库（68 目录 = 66 表 + `_meta`/`_logs`，约 598 MB）与主库口径/授权/断点体系均不同 |
| 决策 | 独立库根 `D:\全量数据\alt_data` + 独立断点 + 独立规格（`config_alt`/`alt/spec.py`）+ **`assert_writable()` 硬保护**（越界抛错并计入 `_VIOLATION_LOG`）；主库对 alt 仅作**只读联查**（R14 契约） |
| 备选 | 合并为一个大库（否决：口径污染 + 授权混淆 + 断点体系冲突）；松散约定（否决：无法取证） |
| 理由 | 隔离必须**可观测**：`violation_count()` 把"是否试图越界"从推断升级为证据（10 §15.4） |
| 后果（正） | 主备互不污染；越界尝试留证 |
| 后果（负） | 联查需显式跨库（默认 `how='left'` 匹配率仅 3.3% 的坑，R14 已断言） |
| 复评触发 | 出现跨库高频联查需求（→ 评估物化视图/轻量对账表） |

## ADR-11 · 调度与运行：系统级定时 + CLI 注册表，不引入编排引擎

| 项 | 内容 |
|---|---|
| 状态 | **已服役** |
| 背景 | 日更 17:30（WorkBuddy），派生/扫描 18:00+，看板/推送 21:30；任务规模 < 20，依赖简单（顺序 + 少量条件） |
| 决策 | 定时由系统级调度器触发 `main.py` 子命令；任务编排写入 CLI（36 子命令注册表，`db` 命令族 + 隐藏兼容别名） |
| 备选 | Airflow/Dagster/Prefect（否决：需常驻服务与元数据库，规模不匹配）；纯脚本串行（否决：无统一入口与退出码语义） |
| 理由 | CLI 注册表提供**统一入口 + 退出码门禁 + 可回归**（R1 契约），成本远低于编排引擎 |
| 后果（正） | 零运维；每个命令可单跑可编排；退出码即门禁 |
| 后果（负） | 依赖关系隐含在脚本与时刻表（无显式 DAG）；失败重试策略需自行实现 |
| 复评触发 | 任务 > 20 或需要显式依赖编排/重试策略 |

## ADR-12 · 文档与真源：文档是真源的导出物，不手工维护数字

| 项 | 内容 |
|---|---|
| 状态 | **已定**（K1 兑现） |
| 背景 | README 快照表与 05 §20.2 字典中的数字均为手工抄录的实测值，必然过期（R-9） |
| 决策 | ① 文档中的**结构性数字**（表数/目录数/行数/体积/列）由 `db-schema --json` 渲染生成 ② 文档只手工维护**结论与判断**，不维护可自动生成的数字 ③ 每次修订登记（README §七），超 3 处实质修订升 minor |
| 备选 | 手工维护 + 定期核对（否决：已证明会漂移）；文档即真源（否决：与 `config.py` 冲突） |
| 理由 | 一处真源（`config.py` + 磁盘）→ 一处生成 → 多处引用；引用不复制 |
| 后果（正） | "文档数字过期"从风险变为不可能；评审可直接比对生成物 |
| 后果（负） | 需维护生成脚本与渲染模板；叙事性判断仍需人写 |
| 复评触发 | 出现"生成物与叙事段落自相矛盾" |
