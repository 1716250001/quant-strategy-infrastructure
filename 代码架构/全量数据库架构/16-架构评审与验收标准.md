# 16 · 架构评审与验收标准（第 32 章）

> 一句话：**评审不接受"看起来对"，只接受"可复跑、可复核、可销项"**。本章给出验收尺子、硬性要求对照、门禁命令、评审机制与留痕格式。
> 事实锚点：2026-09-30（`main.py` 36 子命令、`regress` 16 组、`db-audit` 四类体检、库编目 113 目录）。
> 与 09 §14.10（SLO/门禁源）、11 §17（风险登记）、15 §31（反模式）配套；本章不含编码排期（豁免 18/19 号）。

---

## 32.1 验收尺子（8 项判据）

| # | 判据 | 通过标准 | 证据形式 |
|---|---|---|---|
| **J1 事实可复核** | 结论必须带 `文件:行号` 或**实测命令 + 日期**（INV-10） | 抽查 10 条结论，全部可复跑或可定位 | 命令输出 / 代码行 |
| **J2 真源唯一** | 表规格仅来自 `config.py`；文档为导出物（INV-1） | 全库检索无第二处表清单 | `search_content` 结果 |
| **J3 布局可控** | 布局仅由 `table_storage_layout` 判定；无混合布局（INV-2） | `regress` R8/R9 绿 | 回归输出 |
| **J4 幂等与断点可信** | 落盘先于断点（INV-3）；重跑零追加 | `db-audit` 重复数 = 0；重跑行数不变 | 体检输出 |
| **J5 只读与隔离** | 消费侧只读；alt 不写主库（INV-4/INV-5） | 无旁路写入；`violation_count()` 审查记录 | 代码检索 + 日志 |
| **J6 失败可见** | 无静默失败；告警分级（§28.2）；显式豁免有据（INV-6） | 演练注入失败必被报出 | 演练记录 |
| **J7 可复算** | 结论可带 `db_version` + `date_max` 复算（08 §13.7） | 抽查消费侧结论可复算 | 复算记录 |
| **J8 缺口可归因** | 缺口三类归因完整；真缺口无 core 表 | `db-audit` 输出三类计数 | 体检输出 |

> **尺子怎么用**：8 项中任一项不通过 = 架构验收**不通过**（不是"待改进"）；改进项另列（32.5 销项表）。

## 32.5 评审机制与缺陷分级

**单人场景的"外部化"**（沿用并强化）：

| 手段 | 做法 |
|---|---|
| 证据外部化 | 所有结论带命令与日期（J1），他人可独立复跑 |
| 断言外部化 | 把评审关注点写成 `regress` 断言（R1-R16 即历史评审的产物） |
| 判据外部化 | SLO/阈值写入 `config.py`（唯一真源），不靠记忆 |
| 反例外部化 | 每条断言带反向对照（R15/R16 范式），防假绿 |
| 变更留痕 | 32.6 留痕表 + `db_version.json` |

**缺陷分级与销项规则**：

| 级别 | 定义 | 销项要求 |
|---|---|---|
| **P0** | 破坏主干数据 / 静默失败 / 无回滚路径 | 立即止损 + 根因 + **新增断言**（无断言不算销项） |
| **P1** | 关键表质量或权限断裂 | 修复 + 断言或监控 + 台账登记 |
| **P2** | 非核心偏差、文档不符、效率问题 | 修复或显式豁免（附理由） |
| **P3** | 表达/格式问题 | 下次修订顺带处理 |

**销项闭环三件套**：① 复跑证据 ② 新增/更新断言（或显式豁免）③ 留痕记录。**"改了但没断言"= 未销项。**
