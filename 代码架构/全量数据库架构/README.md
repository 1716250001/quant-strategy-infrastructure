> 项目代号：**MD-Foundation（mdf）**——A 股/基金/债券/期货/期权/海外多口径的**全量市场数据库**体系，覆盖采集 → 落盘 → 治理 → 服务四段。
> 文档体系版本：**v0.1（首版设计稿，未冻结）** ｜ 创建：2026-09-30 ｜ 蓝本：`代码/代码架构/回测工具架构/`（33 章同构映射）

> **当前状态**：主库在线服役（日更 17:30 在跑）、读侧契约已固化、写侧为**单机 Parquet 数据湖（目录即分区）**；本文档同时给出**现状架构（as-is）**与**目标架构（to-be）**，目标态边界见 §11 路线图与 §21 PoC 清单。

## 一、本文档体系是什么

为**"一个长期自我维护的全量市场数据库"**设计的探索性、基础性、完整性架构文档：不是某张表的取数说明，也不是某个脚本的设计，而是覆盖**采集 → 落盘 → 治理 → 服务 → 观测**全链路的架构蓝图。

### 已确认的四项关键决策（2026-09-30）

| # | 决策项 | 结论 |
|---|---|---|
| 1 | **数据范围** | A 股为主干（日线/财务/资金/事件/两融/期权/期货/指数），基金与可转债同等对待；海外与宏观由 `alt` 库并列承载；**分钟级与 Level2 明确不入库**（盘中走网页直连通道） |
| 2 | **存储形态** | **单机 Parquet 数据湖，目录即分区**（`by_year` 主流 + `single` 元数据 + 仅 `stock_company` 保留 `by_code`）；MVP 不引入 OLTP/列存引擎（ADR-1） |
| 3 | **读写分离** | 写侧只经 `fetch/backfill.py` 引擎 + `common/parquet_store.py` 落盘器；读侧双分支：维护层 `common/reader.py`（纯本地、fail-fast）与决策层 `赤潮/market_data.py`（线上 API ↔ 本地库、可降级） |
| 4 | **可信基线** | 单一真源（`config.py` 规格 / `common/paths.py` 路径 / `common/calendar.py` 日历）+ 断点三态 + **落盘先于记断点** + 回归断言守卫，库可被独立复算与验收 |

### 文档写作纪律（继承蓝本）

- **不写生产实现代码**：仅允许接口签名（`typing.Protocol`）、伪代码、YAML/JSON Schema、DDL 片段、Mermaid 图、表格。
- **标注体系全文统一**：`[假设]` · `[待验证]` · `[开放问题]` · `[风险]`。
- **区分现状与目标**：每章区分 as-is（已服役事实）与 to-be（建议/待建），并标注 MVP 取舍（先做/后做/明确不做）。
- **事实必带口径日期**：数字标注实测日期与来源（`路径:行号` 或文档 §）。
- 中文撰写，术语中英对照（术语表见 17 号）。

## 六、与蓝本的差异（豁免说明）

1. **按任务书豁免两份**：不设「分步编码计划」与「架构审查与重构方案」类文档。实施排期并入 11 号（MVP/路线/里程碑），评审留痕以附录形式并入 16 号（§32.6 起）。
2. **章节同构但语义替换**（数据库语境）：蓝本"回测-实盘一致性"→ 本体系"读侧一致性与消费契约"；蓝本"微观结构与执行建模"→ 本体系"增量、分页与并发写建模"；蓝本"多资产与衍生品建模"→ 本体系"多源、主备与多资产建模"；蓝本"偏差与过拟合治理"→ 本体系"数据质量、偏差与稳健性治理"；蓝本"实验管理"→ 本体系"数据版本与可回溯"。
3. 蓝本的服务对象是"回测引擎"，本体系的服务对象是"**全部消费侧**（回测/决策/看板/研究）"，因此新增**读侧双分支契约**与**只读隔离**专章（14 号 §23）。
