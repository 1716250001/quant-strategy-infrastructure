# 02 · 参考系统对照与借鉴（章 5）

> 目的：为本库的四个关键决策域（**存储格式 / 版本与回溯 / 质量与契约 / 读取服务**）建立参照系，明确"学什么、不学什么、为什么"。
> 纪律：对照项只写**可核验的机制性事实**，不做厂商性能宣传引用；采纳/不采纳结论必须落到 ADR 或章节。

---

## 5.1 八类参考系统

### R1 本体系自身（作为参考系）

| 维度 | 事实 |
|---|---|
| 已服役机制 | `by_year` 目录分区、断点三态、落盘先于记断点、回归断言、体检四类、双读取层 |
| 已有文档资产 | `数据与工程/`（格式与读取说明、结构总览、权限总账、读取层分工）、`代码架构/回测工具架构/`（33 章架构方法论） |
| 借鉴结论 | **本体系的方法论（事实锚定 + 标注体系 + 章节可追溯）直接沿用到本目录**；数据工程事实以 `数据与工程/` 为准 |

### R2 经典分区数据湖（Hive 风格：目录即分区）

| 对照 | 评价 |
|---|---|
| 相同点 | 分区裁剪（predicate pushdown）与"分区键在路径"的思路一致；本库 `by_year` = `ds=YYYY` 的退化形态 |
| 差异 | Hive 用 `key=value` 显式分区路径 + metastore 登记 schema；本库用裸年份文件名，**schema 无 metastore**（靠 `config.py` + `db_schema.json`） |
| 借鉴 | 采纳**分区裁剪**与**分区键不可变**原则；不采纳 metastore（重）：以 `db_schema.json` + `TABLE_DATE_COL` 做轻登记 [开放问题]：是否引入 schema 版本号与列级变更记录 |
| 落点 | 05 §9.3、14 §22（分区与压缩） |

### R3 湖仓表格式（Delta Lake / Apache Iceberg / Apache Hudi）

| 对照 | 能力 | 本库现状 | 结论 |
|---|---|---|---|
| ACID 表 | 事务提交与并发写安全 | 无（单进程假设 + 原子 replace） | **MVP 不采纳**：引入需重写全部落盘路径（ADR-1） |
| 时间旅行 | 按版本/时间读历史快照 | 无（覆盖写即不可回溯） | **部分采纳**：以"关键表日/周快照 + 变更留痕"低成本近似（PoC-2） |
| schema 演进 | 加列/改类型可追踪 | 无显式策略（pandas 落盘即覆盖 schema） | **采纳其思想**：列级变更须登记 + 断言（09 §14.5） |
| 小文件治理 | compaction | 已由"按年大表"从根上避免小文件 | 现方案已优于其默认状态 |
| 落点 | 08 §13（版本）、12 ADR-2/ADR-3、14 §22 |

### R4 数据版本与血缘（DVC / LakeFS / dbt）

| 系统 | 核心机制 | 借鉴 | 落点 |
|---|---|---|---|
| DVC | 数据文件哈希 + 指针入仓 | 采纳"**内容寻址摘要**"：为关键表生成行数+内容摘要（digest）作为可比对指纹 | 08 §13.4、09 §14.6 |
| LakeFS | 分支/提交/回滚语义 | 不采纳（需对象存储与服务端）；其"提交前校验"思想 → 采纳为"入库前断言" | 09 §14.3 |
| dbt | 模型即代码 + 测试即契约 + 血缘图 | **强借鉴**：表规格声明化（`config.py` 规格 + 断言清单）= dbt 的 `schema.yml` + `tests`；血缘以"派生输入表清单"表达 | 14 §26、05 §20.6 |

### R5 数据质量框架（Great Expectations / Soda / Pandera）

| 系统 | 核心机制 | 借鉴 | 落点 |
|---|---|---|---|
| Great Expectations | Expectation 套件 + 文档化数据文档 | 采纳"**期望即断言**"：把现有体检判据（缺口/重复/规模）升级为可版本化套件 | 09 §14.2、15 §27 |
| Soda | 声明式检查 + 分级告警 | 采纳"**分级**"：core 失败须阻断，extend 失败仅告警 | 15 §28.2 |
| Pandera | 列级 schema 校验（dtype/范围/枚举） | 采纳"**列级契约**"作为 `db-schema` 的扩展字段（dtype/单位/可空） | 05 §20.4 |

### R6 读侧查询引擎（DuckDB / ClickHouse / QuestDB）

| 系统 | 适用性评估 |
|---|---|
| DuckDB | **部分采纳（推荐）**：可直接读 Parquet（`read_parquet` + 谓词下推），适合临时分析与体检加速；不改变存储形态、无服务端 |
| ClickHouse | 不采纳：需常驻服务与数据导入，单机 7.4 GB 规模下 ROI 为负；其物化视图思想 → 采纳为"预计算派生表"（`market_state`/`signals` 已如此） |
| QuestDB/TimescaleDB | 不采纳：面向高频时序写入；本库日频、批写为主 |
| 落点 | 07 §12.4（查询层选型）、06 §10.6（体检加速） |

### R7 量化平台数据层（qlib / ArcticDB / LEAN / vnpy）

| 平台 | 机制 | 借鉴 | 落点 |
|---|---|---|---|
| qlib | 自研二进制 dataset（表达式引擎 + 缓存） | 不采纳存储形态；采纳"**表达式层与存储分离**"（指标在消费侧计算，本库只存观测值） | 12 ADR-4 |
| ArcticDB | 版本化列存（per-symbol 版本链） | 不采纳引擎；采纳"**按标的可追溯**"目标（PoC-2 的最小验收） | 11 §21 PoC-2 |
| LEAN/Zipline | 统一 DataFeed 抽象（多源同接口） | **强借鉴**：本库 `reader` 即 DataFeed；建议加"数据源适配器"概念对齐多源（主库/alt/Wind/网页） | 04 §8.3、14 §25 |
| vnpy | 网关抽象 + 事件引擎 | 借鉴"**网关=数据源适配器**"的显式生命周期（连接/限频/重试/断点） | 04 §8.3、06 §10.2 |

### R8 商用终端与数据服务（Wind / Choice / Tushare / akshare）

| 维度 | 借鉴 |
|---|---|
| 口径披露 | 商用终端对"单位/复权/停牌/停更"有显式口径说明 → 本库采纳为**列级单位与口径字段**（`db-schema` 扩展） |
| 授权分层 | 权限档位与接口白名单 → 本库采纳为 `LEAKY_PERMISSIONS` 监控 + 替代源（14 §25） |
| 停更处理 | 终端以"停更标记"处理退出品种 → 本库采纳为**显式停更清单**（Wind 44 只停更判定、`alt` 已知停更） |
| 结论 | 不采纳其"黑箱计算指标"（如复权因子由终端直接给出）；本库坚持**存原始观测值 + 消费侧计算** |

## 5.2 借鉴结论汇总（采纳 / 不采纳）

| # | 借鉴结论 | 类型 | 落点 |
|---|---|---|---|
| B1 | 分区键不可变 + 分区裁剪；schema 轻登记（`db_schema.json` + `TABLE_DATE_COL`） | 采纳（已在用） | 05 §9.3 |
| B2 | 内容摘要指纹（行数 + digest）作为可比对资产 | 采纳（待建） | 08 §13.4 |
| B3 | 关键表日/周快照 + 回滚（Delta 时间旅行的低成本近似） | 采纳（PoC-2） | 08 §13.3、12 ADR-3 |
| B4 | 列级契约（dtype/单位/可空/枚举）机读化 | 采纳（PoC-1） | 05 §20.4、12 ADR-9 |
| B5 | 期望即断言 + 分级告警（core 阻断 / extend 告警） | 采纳 | 09 §14.2、15 §28.2 |
| B6 | 血缘以"派生输入表清单 + 生成函数"声明显式化 | 采纳（轻量） | 14 §26.4 |
| B7 | DuckDB 作为**读侧临时分析/体检加速**通道（不改存储） | 采纳（可选工具） | 07 §12.4 |
| B8 | 表达式层与存储分离：主干只存观测值 | 采纳（已在用，写入纪律） | 12 ADR-4 |
| B9 | 数据源适配器显式生命周期（连接/限频/重试/断点/权限标记） | 采纳（现有 base.py 抽象即此形态） | 04 §8.3 |
| B10 | 停更显式清单 + 替代源策略 | 采纳（已在用，需制度化） | 14 §25.3 |
| B11 | 表格式引擎（Iceberg/Delta/Hudi）、ClickHouse/Timescale、metastore、LakeFS 服务端 | **不采纳** | 12 ADR-1 |

## 5.3 与蓝本（回测工具架构）的对照

| 蓝本做法 | 本体系对应 |
|---|---|
| 参考系统对照 → 借鉴结论 → ADR 三段式 | 完全沿用（本章 → 12 号 ADR） |
| 事实锚定（数据底座快照） | 沿用并**升级为可复算编目**（`.temp/_db_catalog_*.tsv`，Footer 只读扫描可重跑） |
| 多轮独立评审 + 销项表 | 沿用（16 号 §32.6 起留痕；本体系豁免"审查/重构方案"独立文档） |
| 不写生产代码、仅签名与图 | 沿用 |
