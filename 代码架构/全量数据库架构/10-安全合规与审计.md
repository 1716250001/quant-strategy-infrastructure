# 10 · 安全、权限、合规与审计（第 15 章）

> 一句话：本库的安全问题**不是"防黑客"**，而是四件事——**凭据不泄露**、**权限漏网不静默断裂**、**写通道只此一条**、**对外分发有据可依**。
> 事实锚点：2026-09-30 实测（`代码/config.py:1716-1792` 漏网清单、`代码/config_alt.py::assert_writable`、`fetch/base.py` 权限判据）。
> 与 14 §25（多源主备与授权降级）、06 §10.2（日更告警时序）、09 §14.4 R15 配套；风险登记见 11 §17。

---

## 15.1 安全模型与资产分级

**部署形态决定了威胁模型**：单机、单用户、无对外服务、无网络暴露面。因此风险不来自入侵者，而来自**自己人无意破坏**与**外部授权变更**：

| 资产 | 敏感度 | 主要威胁 | 现有防线 |
|---|---|---|---|
| 库数据（`D:\全量数据\`） | 高（资产与授权价值） | 误写覆盖、外泄、离线丢失 | 只读纪律 + 写通道唯一 + 冷备 |
| 三方凭据（`TS_TOKEN`/`PUSHPLUS_TOKEN`/`WIND_API_KEY`） | **最高** | 硬编码入仓、日志回显、截图外泄 | 环境变量优先、不入仓 |
| 写通道（`fetch/backfill.py` + 落盘器） | 高 | 旁路脚本直写目录、混合布局 | 布局守卫 + 回归断言 + 只读约定 |
| 配置真源（`config.py`） | 高 | 误删条目、口径漂移 | `config-check` + R11 条目数下限 |
| 派生与推送产物 | 中 | 未披露口径被当作事实引用 | 血缘声明 + 来源标注 |

**不变式**：

- **INV-4（主干只读 / 写通道唯一）**：消费侧（回测/决策/看板）对 `market_data` **只读**；写入仅经落盘器。
- **INV-5（并列库隔离）**：`alt_data` 永不写主库；主库永不写 `alt_data`。
- **INV-9（漏网接口不得作为方案依赖）**：任何方案若依赖 15.3 的 7 项接口，必须同时给出替代或降级路径。

## 15.2 凭据与密钥管理

**取值优先级（现状，已实现）**：

```
环境变量  >  代码/.env  >  空（调用前报错，不静默降级）
```

| 凭据 | 用途 | 失效后果 | 处置 |
|---|---|---|---|
| `TS_TOKEN` | Tushare Pro 主库全量取数 | 全部日更/补数失败 | 立即续费/换档；告警 |
| `PUSHPLUS_TOKEN` | 告警推送（日更摘要、权限告警） | 失败不可见（**静默**） | 降级为控制台输出 + 次日体检发现（15.5） |
| `WIND_API_KEY` | Wind 自编指数线（现停更 09-21） | 指数线不更新 | 显式停更清单（05 §20.5 GS-6） |

**纪律（现状已遵守，本章固化为条文）**：

1. 禁止硬编码：任何 `.py` 内不得出现令牌明文；`.env` 不入版本库、不进备份包（冷备脚本须排除）。
2. 不回显：日志/异常信息中令牌一律脱敏（`****` 尾 4 位或全掩）。
3. 可轮换：更换令牌只改环境或 `.env`，不改代码、不改库。
4. 可观测：日更开始记录 `env 指纹`（哈希后 8 位，不记原文），便于事后判定"是换了令牌还是别的变了"。
5. 单点已知：当前三把钥匙均由单人保管 [风险] → 登记在 11 §17（R-凭据单点），缓解措施为离线备份 + 恢复文档。

## 15.3 权限档位与漏网接口治理

**事实（2026-09-20 全库筛查 239 接口实测）**：账号为 **2000 积分档**；筛查确认 **7 项"漏网"**——官方标称门槛高于本档、但实测可调。判定为**平台权限校验缺口**，非门槛下调，三条证据：① 同档对照接口 `fund_portfolio` 稳定报"无权限" ② 官方文档至今未改 ③ 平台无公告。

| 接口 | 官方门槛 | 类型 | 下游用途 | 替代路径 | 纳入告警 |
|---|---|---|---|---|---|
| `share_float` | 3000 积分 | quota | 解禁压力预判 | akshare `stock_restricted_release_*` 五件套（细节更全） | 是 |
| `index_dailybasic` | 4000 积分 | quota | **奇点估值锚点（PE/PB/股息率）** | 乐咕（**月频**）／中证官网（仅近 1 月）→ **替代不完整** | 是 |
| `fund_adj` | 5000 积分 | quota | **宽基 ETF 轮动复权价** | 净值 + 分红自算（**精度未验证**）→ **替代不完整** | 是 |
| `opt_daily` | 5000 积分 | quota | 期权杠杆监控（运行时调用） | akshare `option_sse_daily_sina`（部分覆盖） | 否 |
| `hk_daily` | 独立权限 1000 元/年 | indep | 港股日线 | akshare `stock_hk_daily`（新浪源，2004 起） | 是 |
| `us_daily` | 独立权限 2000 元/年 | indep | 美股日线 | akshare `stock_us_daily`（新浪源，1984 起，延迟 15 分钟） | 是 |
| `broker_recommend` | 6000 积分（官方表未列此档） | quota | 券商月度金股 | akshare `stock_institute_recommend` → **实测返空，替代不成立** | 是 |

**核心风险（原文口径）**：漏网状态**不可作为长期依赖**。平台一旦收紧，这些表会**静默断裂**（返回"您没有接口(xxx)访问权限"），而体检只能看到"数据落后 N 天"，**分辨不出是权限收紧还是网络故障**。

**治理机制（现状，三处消费同一份清单）**：

| # | 落点 | 行为 |
|---|---|---|
| 1 | `fetch/base.py::ts_call_with_retry` | 命中无权限 → **只调 1 次不重试**（实测重试 5 次白等 18.5 秒）+ 打印 ★ 提示与替代路径 |
| 2 | `fetch/daily_update.py` | 日更结束汇总告警（PushPlus）：把"断了一个月才发现"变成"**收紧当天就知道**" |
| 3 | `tools/regress_pipeline.py` R15 | 交叉验证清单与 `BACKFILL_TARGETS`（表名必须真实存在、五字段齐全），防清单打错表名导致监控空转 |

**清单字段契约**（`LEAKY_PERMISSIONS`，`config.py:1734-1739`）：`claimed`（官方门槛）/ `kind`（`quota`｜`indep`）/ `use`（影响面）/ `alt`（替代路径）/ `monitor`（是否告警）。

**判定纪律**：

- 无权限错误**永久性**，不得重试；限频错误需等 `RateLimiter` 预约；网络错误按退避重试——**三类必须分开**（R15 判据：无权限 N 例识别 + 限频/网络 N 例不误伤）。
- 若某接口被收紧但**已在库内**（历史数据仍在），影响面按"能否续更"评估，不按"表是否存在"评估。
- **升档决策触发条件**：任一 `monitor=True` 接口连续 3 个交易日被拒，且其替代路径被标注为"不完整/不成立" → 触发档位升配评估（11 §17 R-授权）。

## 15.4 只读隔离、写通道唯一与数据合规

### 只读隔离（现状，已机器化）

| 边界 | 保护手段 | 越界后果 |
|---|---|---|
| 消费侧 → `market_data` | 约定 + 代码审查；写侧 API 不在 `reader` 命名空间 | 混合布局 / 覆盖写（**设计上不可能经由 reader**） |
| `alt_data` → 主库 | `config_alt.assert_writable(path)` **硬保护**：目标必须位于 alt 授权区 | 抛错 + 计入 `_VIOLATION_LOG`（越界**尝试**即留证） |
| 派生任务 → 主干 | 派生只写自己的目录（`market_state`/`custom_index`/`signals`） | INV-7 违规，按事故处理 |
| 文档/工具 → 库 | 全部只读或 dry-run（09 §14.1 纪律 1） | — |

**Violation 取证（alt 越界写主库）**：`assert_writable` 已把"是否**试图**越界"从推断升级为**直接可观测**（`violation_count()`，夹逼前后取差即可判定）——因为"metadata 目录没变 → 变化必是主库自己写的"只是推断，alt 真越界写会被夹逼误判为 external 并抹掉痕迹。

### 写通道唯一

```
三方 API ─▶ fetch/*.py ─▶ common/parquet_store.py（LayoutGuardError 守卫）─▶ 库
                              ▲
                       唯一落盘入口
```

**纪律**：新增取数脚本必须走落盘器与 `table_storage_layout`；**禁止任何调用方自行拼接年度路径**（README §五 布局真源）。

### 数据合规（现状 + 预留）

| 事项 | 现状 | 规则 |
|---|---|---|
| 数据授权范围 | Tushare Pro（个人档）+ akshare（开源接口）+ Wind（本地终端） | 各源授权**仅限自用研究**；条款登记在 `文档/数据与工程/`（事实来源） |
| 对外分发/转售 | **明确不做**（01 §2.2 N8） | 不得整库/整表分发；演示材料使用聚合统计或极小切片 |
| 切片导出 | 仅在明确对外交换时进行（05 §20.8 S-MIN~S-ALT 为交付形态） | 需登记：用途、接收方、范围、期限；禁止导出可还原全历史的切片 |
| 派生数据 | 派生物同样受源数据条款约束 | 不得因"自己算的"而视为自有权 |
| 停更数据处理 | 停更表（`gz_index` 止 2019、Wind 指数止 2026-09-21）仍在库 | 保留但**显式标注停更**（防被当现状） |

**红线（一句话）**：**库里的一切，对消费侧只读；库外的一切，未经登记不得分发。**

## 15.5 审计留痕与取证

留痕的目标不是"合规摆设"，而是**事后能回答三个问题**：数据当时是什么、谁改的、为什么改。

| 留痕 | 载体 | 记录内容 | 保留策略（建议） |
|---|---|---|---|
| 断点 | 库根断点 JSON（4 个：`.backfill_checkpoint.json` 4.32 MB / `.bak_20260925_220428` 4.05 MB / `.checkpoint.json` 1.91 MB / `.cb_checkpoint.json` 23 KB） | 每表完成日期/行数/状态（done/partial/failed） | 永久 + 每季度快照 |
| 数据版本 | `metadata/db_version.json`（08 §13.5） | 版本号、变更表清单、快照指针 | 永久（小文件） |
| 快照 | `_snapshots/YYYY-MM-DD/manifest.json` | 行数/schema_hash/digest | 30 天 [建议] |
| 日志 | `LOG_DIR` 下日更/补数日志 | 每接口耗时、行数、重试、错误分类 | 90 天 [建议] |
| 告警 | PushPlus 推送记录 + 状态文件 | 权限告警、失败摘要 | 90 天 |
| 越界尝试 | `config_alt::_VIOLATION_LOG` | 越界路径、时间、调用栈 | 永久（体积极小） |
| 元数据指纹 | R16 的 `metadata/` 指纹（相对路径+size+mtime_ns 逐文件） | 软改动的观测面 | 每次 dry-run 断言即比 |
| 基准记录 | `metadata/bench_log.jsonl`（09 §14.7，to-be） | 每任务行数/秒数/调用数 | 1 年 |

**取证能力（现状已有）**：

1. **归属判定**：`metadata/` 指纹变化 + 夹逼法 → 区分"主库自己写的" / "alt 越界写的尝试" / "外部改动"。
2. **变更解释**：`db_version.json` 的 `tables_changed` 必须能解释当次所有行数变化；解释不了的差异 = 缺陷（INV-10 同源：结论可复核）。
3. **静默失败不可留痕**，因此 **静默失败即违规**（09 §14.8 判据共性）——所有失败必须落到日志或告警。

**审计动作（建议节奏）**：

| 节奏 | 动作 | 输出 |
|---|---|---|
| 每日 | 日更摘要（成功/失败/告警）推送 | 一行可读结论 |
| 每周 | `db-audit` 四类 + `freshness --all` | 结论存档 |
| 每月 | 断点×磁盘交叉核对（`ckpt --show --json`）+ 停更清单复核 | 差异清单 |
| 每季度 | 权限漏网 7 项抽检（实调验证是否仍可用）+ 恢复演练 | 授权状态表 + 演练记录 |

## 15.6 访问控制与角色（现状 → to-be）

**现状**：单机单用户，无登录体系；访问控制**全部靠文件系统权限与约定**。

| 角色 | 现状 | to-be（建议，MVP 后） |
|---|---|---|
| 库维护者（写权限） | 唯一用户 | 保持单人；写操作留痕（日志） |
| 消费侧（回测/决策/看板） | 同机同用户，约定只读 | 只读账号或只读挂载；`reader` 为唯一入口 |
| 研究/新人（取切片） | 人工交付 | 用 S-MIN~S-ALT 切片（05 §20.8）+ 读取脚本 |
| 外部（无） | 不存在 | 不开放 |

**可见性提醒**：本机多用户环境下，`D:\全量数据\` 的 ACL 即实际权限边界——**"约定只读"不等于"不可写"** [风险]（11 §17 R-隔离靠约定）。缓解：写侧 API 收敛到落盘器 + 建议对消费侧进程使用只读挂载/复制副本。

## 15.7 合规预留（前瞻，不阻塞 MVP）

| 议题 | 触发条件 | 预留动作 |
|---|---|---|
| 数据授权条款变更 | 源方改条款/涨价/停服 | 条款快照归档（日期+原文）+ 影响面清单（哪些表依赖该源） |
| 凭据集中化 | 多人协作或多机部署 | 引入密钥管理（环境变量注入 → 密钥服务），禁止 `.env` 明文外传 |
| 数据出境/跨境 | 引入海外数据线并对外交付 | 单独评估（现在 `us_daily_qfq` 等仅自用） |
| 审计合规（可追溯要求） | 有人要求"某日某表数值" | 快照 + `db_version.json` 支撑（PoC-2 兑现后达标） |
| 脱敏/最小化 | 对外交付含个股明细 | 默认给聚合口径；明细需登记 |
