## 33.2 关键状态机

### ① 断点状态机（每表每任务）

```
        ┌──────────── 落盘成功 ────────────┐
        │                                  ▼
   [pending]  ──落盘成功──▶  [done]  ──同表重跑/增量──▶ [done]
        │                      │
        │                      └──部分分区完成──▶ [partial] ──续做成功──▶ [done]
        │
        └──失败/中断──▶ [failed] ──重跑──▶ [done|partial]
```

| 状态 | 语义 | 允许的后续 | 体检表现 |
|---|---|---|---|
| `pending` | 应做未做（虚记风险点） | 执行 | G4 门禁：不得存在虚记 |
| `done` | 水位可信（与磁盘一致） | 增量 | 正常 |
| `partial` | 部分完成（如分页中途） | 续做 → `done` | 需在告警中列明 |
| `failed` | 失败待重试 | 重跑 → `done`/`partial` | P1 告警 |

**规则**：状态推进**只能由落盘成功后触发**（INV-3）；`ckpt --show` 必须能与磁盘交叉核对（双校验）。

### ② 落盘事务状态机

```
读取(pages) ─▶ 去重(_concat_pages/drop_duplicates) ─▶ 写 tmp ─▶ os.replace ─▶ 记断点
     │                    │                              │           │
   失败→不落盘          失败→不落盘                  中断→tmp 残留   失败→重试(幂等)
                                                        （可识别可清理）
```

**不变式**：任何中断点都不产生"半写文件被读者看到"（原子写）；`tmp` 残留由扫描排除。

### ③ 漏网授权状态机

```
[可用(漏网)] ──被拒(无权限)──▶ [疑似收紧] ──连续 3 交易日──▶ [实质断裂]
     ▲                              │                            │
     └──────── 复检仍可用 ───────────┘                    替代/降级启用
                                                替代不完整 → 升档评估（ADR-8）
```

**判定**：`monitor=True` 接口被拒 → 当日告警（P1）；不重试；记录到台账。

### ④ 迁移状态机

```
[在线] ─冻结─▶ [冻结中] ─迁移脚本─▶ [已迁移] ─守恒校验─▶ 通过 ─▶ [验收] ─登记─▶ [上线]
                   │                    │                    │
                   └──失败──▶ 回滚 ◀──校验不过(≠0)───────┘
```

**规则**：冻结期间停写；校验 `rows_before − rows_after − dedup_removed == 0`（15 §30.2）；验收必须含 `db-audit` + 抽样比对。

### ⑤ 派生重建状态机（INV-7）

```
[输入就绪] ─读主干(只读)─▶ [计算] ─▶ 写派生目录 ─▶ [可服务]
                                   │
                                   └──失败──▶ [缺失] ──重建──▶ [可服务]
```

**规则**：派生失败**不影响主干**；重建必须幂等（同输入同输出）；输入版本须登记（R-8）。

### ⑥ 库版本状态机

```
[N 版在线] ─增量日更──▶ [N 版]（内容变，版本号不变；变更集记入 db_version）
     │
     └──结构性变更（迁移/改列/改口径）──▶ 版本号 +1（minor/major）─▶ 快照 + 通知消费侧
```

**规则**：**静默改口径 = P0**；版本号变化必须伴随快照或明确说明为何不需要（08 §13.5）。

### ⑦ 轮转水位状态机（list 表，v1.2 设计态）

```
[无水位] ──首次成功落盘──▶ [fresh] ──周期到期(最旧优先)──▶ [stale] ──重拉落盘──▶ [fresh]
     │                                                  │
     └───拉取/落盘失败──▶ [保持原水位]（下轮优先重拉）───────┘
```

| 状态 | 语义 | 体检表现 |
|---|---|---|
| `无水位` | 新标的（清单新增），视为最旧 | 优先拉（自愈） |
| `fresh` | 已在轮转周期内重拉过 | 正常 |
| `stale` | 超期（> 轮转周期 + 缓冲） | P2「轮转停滞」（15 §28.2） |

**规则**：水位**只在落盘成功后推进**（INV-13 / I7）；失败不推进、不报"已完成"。**rebuild 同语义**（F-15）：按**批级收编**——flush 失败批不进入水位与覆盖率（18 §13）。

**`--status --json` 输出契约**（§146 R6S-1；与 `alt/list_backfill.py` docstring 逐字一致）：

```
每表固定键 = {total, fresh, stale, oldest, newest, rotate_done, checkpoint_done}
＋ 异常时附 error。其中：
  · rotate_done      = RotateState（本引擎的轮转水位）条数
  · checkpoint_done  = AltCheckpoint（us_backfill/backfill 的一次性断点）done 条数
两者**互不可见**，故并列输出（§140 R6-1 修的就是"只看前者 ⇒ 显示 done=0 假象"）。
新增/删除键属接口变更，须先获批（§142 R6R-2）后再动。
```

> 为什么必须并列：`us_daily_qfq` 盘上有 3,040 万行、一次性断点 `done=18,052`，但**轮转水位无此表**——
> 只暴露 `fresh/stale` 会让机读侧把它读成"从未拉过"，进而误启动全量重拉（18 §140.0）。

## 33.3 异常类型与一致性契约

### 异常类型（写侧/读侧）

| 异常 | 触发 | 处置 |
|---|---|---|
| `LayoutGuardError` | 写入器与布局期望不符 | 硬拦；修调用方（禁止绕过） |
| `DeprecatedEngineError` | 调用已废弃引擎（`gap_update`/`intraday_update`） | 硬拦；改用新入口（R7） |
| 权限异常 | 命中无权限特征 | 1 次调用即停 + 告警 + 替代路径（14 §24.3） |
| 限频异常 | 命中限频特征 | 等 `RateLimiter` 预约 |
| 网络异常 | 超时/连接失败 | 退避重试（≤ `TS_MAX_RETRIES`=5） |
| 截断标志 | `truncated=True` | 告警"数据可能仍不完整" + 分段/分页补齐 |

### 一致性契约（必须成立）

| 契约 | 判据 | 违反级别 |
|---|---|---|
| 断点 == 磁盘 | `ckpt --show` 交叉核对 | P0 |
| 布局唯一 | 无混合布局、无未登记 `by_code` | P0 |
| 主键无重复 | 按 114 键判重 = 0 | P0 |
| 空 ≠ 0 ≠ 缺失 | 空值语义显式（15 §27.4） | P1 |
| 单位固定 | `vol` 手 / `amount` 千元 / `mv` 万元 / 股本 万股（**alt 港股线除外**：`hk_daily.volume`=股 / `amount`=元，05 §9.5） | P1（改单位 = 不兼容事件） |
| 日期格式固定 | `YYYYMMDD`（月频 `YYYYMM`） | P1 |
| **复权公式** | 股票 = `close × adj_factor / 最新 adj_factor`（**除法型**）；港股 = `close(t) × f_daily(t)`（**乘数型**）——`f_daily` 由**读取层**按"**骨架 = 价格交易日 ∪ 因子事件日**、升序 ffill、`1900-01-01` 哨兵前置"展开（**骨架缺事件日即错价**：实测 237 行偏差 / 最大 80%；两式**不得互换**；**禁止消费侧自行 ffill**）→ R-20。**精度注记（F-13，v1.3）**：官方 qfq 价为 **4 位小数舍入**——对账**禁用裸相对误差**（低价股系统性假阳性），用**绝对误差 ≤ 5e-5**（= 舍入上界） | P1 |
| 联查报匹配率 | 低于阈值必须告警（R14 ①） | P1 |
| 结论带版本 | `db_version` + `date_max`（08 §13.7） | P2 |
| **`us_daily_qfq` 使用禁令**（18 号 §150，2026-10-27 立） | **仅供历史留痕**；**禁止作为任何计算的输入**（估值/回测/**校验基准**皆不可）。实测含 `close ≤ 0` **2,268,315 行 / 30,396,860 行 = 7.462%**（AAPL 10,042 行中 5,346 行为负，自 1987-05-11 起）。美股价格口径一律 `us_daily_raw`（不复权）+ `us_qfq_factor`（因子）经 `expand_us_qfq_factor` **现算**。**另注**：美股哨兵日期实测**两种**——`19700101`（9,117 只）/ `19000101`（8,927 只，因子恒 1.0 表无公司行动），**两者均须保留、均禁按日期阈值剔除** | **P0**（违反 = 污染计算结果） |

## 33.4 标注与用语规范

| 标注 | 含义 | 使用要求 |
|---|---|---|
| `[现状]` | 已在代码/库中实测确认 | 可作事实引用 |
| `[实测]` | 有命令/文件证据（附日期） | 可作事实引用 |
| `[推断]` | 由事实推导、未独立验证 | 需注明推导依据 |
| `[假设]` | 待验证的设定（如阈值） | 不得作为验收依据 |
| `[待验证]` | 已知未验证点 | 列入开放问题或 PoC |
| `[风险]` | 已知风险 | 须在 11 §17 有对应条目 |
| `[建议]` | 本文档提出的改进 | 不构成现状描述 |

**用语规范**：

1. 数字必须可追（命令 + 日期）；文档中的结构性数字以生成物为准（ADR-12）。
2. 不用"大概/应该没问题/一般来说"描述可验证事实。
3. 引用他人结论时给 `文件:行号`（INV-10）。
4. 区分"事实（现状）"与"主张（建议）"——两者不得混写在同一句结论里。
