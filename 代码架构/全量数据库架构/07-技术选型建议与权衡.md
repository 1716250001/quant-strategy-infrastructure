# 07 · 技术选型建议与权衡（章 12）

> 纪律：每项选型给出 **现状 / 候选 / 推荐 / 取决因素 / 何时重估**；不为"新技术"而迁移，**只在触发条件下重估**。

---

## 12.1 存储格式

| 候选 | 评价 |
|---|---|
| **Parquet（现状，推荐）** | 列存、压缩、谓词下推与行组统计（本项目已用其统计做编目）、生态成熟（pandas/pyarrow/DuckDB 通吃） |
| CSV | 无类型无压缩，仅适合交换；已淘汰 |
| Feather/Arrow IPC | 读写更快但无压缩比与生态厚度；适合**中间态**（进程间交换），不适合长期存储 |
| HDF5 | 单文件树结构，损坏难恢复、并发写差；已淘汰 |
| 自研二进制（qlib 式） | 读取极快但生态封闭、调试困难、迁移成本高 |
| 结论 | **保持 Parquet**；仅在"读取延迟成为硬指标"时评估 Arrow IPC 作为缓存层（不改主干存储） |

## 12.2 分区与目录布局

| 候选 | 评价 |
|---|---|
| **按年分区（现状，推荐）** | 已实测 40× 读取提速（`moneyflow` 1 天/分钟 → 41 天/分钟）；文件数可控（`by_year` 文件数 = 年份数） |
| 按月分区 | 文件数 ×12，读单年需拼 12 文件；**无收益**（除非单年文件过大） |
| 按标的（`by_code`） | 适合"单标的时序"访问，但全市场扫描需遍历数千文件；**仅保留给静态元数据**（`stock_company` 5,851 文件） |
| 单文件（`single`） | 用于低频/汇总表（38 目录），避免无意义分区 |
| 按交易日目录（`ds=YYYYMMDD`） | 文件爆炸（万级），写入友好但读取需拼数百文件；**否决** |
| 重估触发 | 单年单表文件 > 2 GB [假设] → 评估"年 + 月"两级；某表全市场扫描占比极高 → 评估列裁剪/预计算 |

## 12.3 压缩算法

| 候选 | 压缩比 | CPU | 适配 |
|---|---|---|---|
| **Snappy（现状默认，推荐）** | 中 | 低 | 日更高频，CPU 敏感 |
| Zstd | 高 | 中 | 冷数据/归档副本；可用 zstd-3 级别再降 20~40% 体积 [待验证] |
| Gzip | 中高 | 高 | 仅冷备，不建议在线读 |
| None | 1× | 极低 | 不推荐（IO 成为瓶颈） |
| 重估触发 | 主库体积 > 15 GB 或冷备空间紧张 → 对"只读历史年"批量转 Zstd（保持读取 API 不变） |

## 12.4 查询与计算引擎

| 候选 | 定位 | 结论 |
|---|---|---|
| **pandas（现状，推荐为主）** | 全链路计算与落盘；生态完备 | 保持（消费侧口径统一） |
| **DuckDB（推荐作为只读加速通道）** | 直接 `read_parquet` + 谓词/列裁剪下推，零落盘、零服务 | **采纳为可选工具**（体检、全市场回放、临时分析）；不改变存储 |
| Polars | 更快、内存更省，但 API 与 pandas 有差异 | 观察（消费侧不强制统一）[开放问题] |
| Spark/Dask | 分布式 | **否决**（单机 7.4 GB，无分布式需求） |
| ClickHouse | 服务化列存 | **否决**（ADR-1） |

## 12.5 元数据与数据字典

| 候选 | 评价 |
|---|---|
| **`config.py` 注册表 + `db_schema.json` 导出（现状，推荐）** | 真源唯一、零运维；缺点是**列级契约与业务语义靠文档**（改进项 PoC-1） |
| Hive metastore / 数据目录服务 | 重（服务常驻），收益是可发现性；**MVP 不采纳** |
| dbt 式 `schema.yml` | **采纳其思想**：列级契约 YAML + 自动生成文档（PoC-1） |
| 重估触发 | 表数 > 200 或参与方 > 3 人 → 需要可发现性服务 |

## 12.6 调度

| 候选 | 评价 |
|---|---|
| **WorkBuddy automation（现状，推荐）** | 已稳定服役（库日更 17:30、扫描 18:00+、作战包 21:30）；零额外设施 |
| Airflow / Prefect / Dagster | 依赖图与重试能力强，但需常驻服务与数据库；**MVP 不采纳** |
| Windows 计划任务 | 备选，功能弱（无依赖编排） |
| 重估触发 | 任务数 > 20 或出现"跨任务依赖 + 需要历史重跑面板"时（推荐 Dagster/Prefect 评估） |

## 12.7 数据版本与快照

| 候选 | 评价 |
|---|---|
| **自建快照（推荐，PoC-2）** | 关键表按日/周 copy 或硬链接到 `_snapshots/`，附 `rows + digest` 清单；实现成本低、无需服务 |
| DVC | 需要 Git 配套与对象存储习惯；本地单机可用但流程偏重 → 采纳"摘要指纹"部分（08 §13.4） |
| LakeFS / 表格式（Iceberg/Delta） | 需服务端或重写落盘 → **否决**（ADR-2/ADR-3） |
| 重估触发 | 回溯需求从"关键表"扩展到"全库逐日" → 评估表格式或快照增量策略 |

## 12.8 交付与推送

| 候选 | 评价 |
|---|---|
| **Markdown 报告 + PushPlus（现状，推荐）** | 轻、可回溯（报告落盘）；缺可视化交互 |
| Streamlit 看板 | 适合体检与库状态可视化（13 号 §19.3）；需常驻进程 → 按需启动 |
| 静态 HTML 报告 | 无服务依赖，适合归档；推荐作为体检报告导出形态 |
| Excel 导出 | 仅用于人工核对（列裁剪后的小样本） |

## 12.9 环境与依赖

| 项 | 现状 | 建议 |
|---|---|---|
| OS | Windows 单机 | 保持；脚本避免 POSIX-only 假设（路径用 `pathlib`） |
| Python | 3.10+（写侧与消费侧同一解释器） | 锁定版本并在 README 记录；升级前跑 `regress` |
| 关键库 | pandas / pyarrow / tushare / akshare / requests | **锁定 minor 版本**；升级须过 `regress` + 抽表行数比对 |
| 凭据 | 环境变量 > `代码/.env` > 空（`TS_TOKEN`/`PUSHPLUS_TOKEN`/`WIND_API_KEY`） | 保持；禁止硬编码（10 §15.2） |
| 依赖安装 | 全局/虚拟环境 [待验证] | 建议写 `requirements.txt` 或 `pyproject.toml` 固化可复现环境（PoC-6） |

## 12.10 选型总表与重估触发

| 域 | 现状 | 推荐 | 重估触发 |
|---|---|---|---|
| 存储格式 | Parquet | **保持** | 读取延迟成硬指标 |
| 分区 | by_year 为主 | **保持** | 单年单表 > 2 GB [假设] |
| 压缩 | Snappy | 保持（冷备可 Zstd） | 全库 > 15 GB |
| 计算 | pandas | 保持 + DuckDB 只读加速 | 体检/回放成为瓶颈 |
| 元数据 | config.py + db-schema | 加列级契约（PoC-1） | 表数 > 200 / 多人协作 |
| 调度 | WorkBuddy | 保持 | 任务 > 20 或需依赖编排 |
| 版本 | 无快照 | 关键表快照（PoC-2） | 出现误覆盖事故 |
| 交付 | Markdown + Push | 加静态 HTML 报告 | 需要历史对比面板 |

**反向选型清单（明确不采纳）**：数据库引擎、元数据服务、分布式计算、对象存储、流式采集、商业数据终端替换（见 02 §B11 与 12 号 ADR-1/2/3）。
